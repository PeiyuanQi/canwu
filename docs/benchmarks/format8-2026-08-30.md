# Format 8 Scale Evidence — 2026-08-30

This artifact records release-mode scale gates for the Format 8 milestone.
These are workstation regression observations, not portable timing guarantees.
The portable contract is deterministic shape, bounded work, typed budget
failure, authenticated provider reads, and content-addressed delta output.

The law storage suite separately covers insertion-order independence,
deletion/rebuild equality, open-ended interval decomposition, content
commitment recomputation, authenticated exact membership, and pathological
overlap returning `QueryBudgetExceeded` before an unbudgeted next provider read.
The production canonical-ingress retention builder emits one authenticated
directory root. While a batch is pending, the retention ledger keeps only the
new object delta and the proposed root's current page closure; the previous
committed root continues protecting older objects and pages. Commit moves the
previous object closure into the new root, swaps the page closure, retires the
superseded root, and clears the terminal handle payload. The plugin reachability
participant therefore expands the current root into the same
one-million-object closure after restart and before GC without retaining one
full closure per historical batch.

The probe streams at most 4,096 hot candidates into each production archive
batch and releases their materialized hot membership after the committed root
swap. Its provider stores canonical JSON values in temporary append-only files
and keeps only content-address-to-offset indexes in memory. Provider reads still
deserialize and verify the same production archive types; the backend does not
bypass read-back verification. Superseded bytes remain physical garbage in the
temporary append files until the probe exits, while the authenticated current
root and reachability walk expose only committed objects. This intentionally
separates logical archive correctness from backend compaction; a shipping
million-record archive should use a disk/object store with its own mark/sweep
or lifecycle policy. Provider bytes and indexed content addresses are reported
above as backend evidence, not hot-engine-state or wire-format guarantees.

## Real Canwu ingress with a large admissible candidate shard

The production-boundary probe persists the complete law plan, directory,
coordinator, archive head, order shard, culture-dependency shard, and a
16,384-candidate retirement shard through ordinary Format 8 domain records. It
then settles one empty calendar boundary and one real `SubmitProposal` legal
ingress. This exercises normal Canwu admission, plugin loading, proposal
validation, atomic domain-record commit, state hashing, and checkpoint revision
instead of calling detached legal-runtime code.

| Metric | Result | Gate |
| --- | ---: | ---: |
| Persisted candidate debt | 16,384 | large admissible fixture |
| Candidate shard encoded bytes | 40,268,744 | below 128-MiB state/memory ceiling |
| Candidate shard version before / after | 1 / 1 | untouched shard is not rewritten |
| Empty boundary elapsed | 169 µs | recorded regression evidence |
| Unrelated legal boundary elapsed | 2,563 µs | recorded regression evidence |

Boundary proposal validation first filters record mutations, then overlays only
the already-changed records onto a structurally shared persistent root and
validates the affected reference closure. A unit gate additionally proves that
an unrelated 1-MiB record payload keeps the same `Arc` allocation through this
overlay path. The earlier implementation materialized every domain record two
times in `DomainDeltaProposal` and once in
`HistoricalCandidateEvaluation`; with the same 16,384-candidate fixture it took
about 1.01 seconds for the empty boundary and 1.82 seconds for the legal
boundary. Those timings are diagnostic pre-fix evidence, not release results.

## Ordinary law boundary versus authenticated root-only history

For each scale, the cold-history probe first constructs and validates the real
authenticated index above, then persists its derived archive head in an
archive-only legal shard. It runs 50 ordinary dirty-shard boundaries without
loading the cold provider.

| ---: | ---: | ---: |
| 100,000 | 6,558 µs | 11,302 µs |
| 1,000,000 | 6,920 µs | 11,733 µs |

The one-million observation is below the 10 ms median and 16.7 ms p95 gates.
Its p95 increased by about 1.2%, below the 10% cold-history growth gate. An
archive-only shard now persists an empty hot shard record alongside its
authenticated head, so root-only restart is valid instead of depending on a
fabricated header fixture.

## Interpretation

- Cold history does not enter ordinary legal shard selection or current-law
  projection reads.
- Domain-record and decision structures use structural sharing; checkpoint
  persistence asks the provider for existing content addresses and emits only
  missing Patricia paths or changed decision buckets.
- Decision controller, ticket, attempt, and trace payloads are shared behind
  persistent tree nodes, keeping fork/COW paths and debug-build stack use
  independent of large inline payload copies without changing the wire shape.
- Root-only restart tests enumerate decision blob locators and legal content,
  blob, membership, effective-time, and recorded-time page IDs through the
  unified archive reachability manifest before offline GC.
- Resident-byte figures are deterministic structural estimates used to catch
  encoding regressions. Host-level RSS and allocator profiling remain separate
  shipping evidence rather than persistence-format guarantees.
