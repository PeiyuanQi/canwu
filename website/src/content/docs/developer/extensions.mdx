参伍的模拟内核保持领域中立。应用通过 `SimulationPlugin`、公开 schema、命令处理器和阶段系统
添加自己的军事、经济、政治或社会规则，而不是修改实时世界对象。

## 选择扩展方式

| 需求 | 使用 |
| --- | --- |
| 一个用户动作或服务请求产生局部变化 | 插件命令 `register_command()` |
| 多个系统在同一日结、回合或时间点协调 | 阶段系统 `register_boundary_system()` |
| 插件拥有类型化领域数据 | 领域 schema 与记录 API |
| 需要稳定随机结果 | 声明并使用插件随机流，让抽样进入证据记录 |

## 命令插件

命令插件应：

1. 提供稳定的名称、版本和 semantic hash；
2. 用 `PluginActionDescriptor` 声明载荷 schema 与读写 `StateKey`；
3. 通过只读 `SimulationView` 查询状态，并根据 `CommandContext` 检查权限；
4. 返回 `SystemDirective` 描述预期变化，而不是直接修改世界；
5. 通过 `Command::Plugin` 从 `submit()`、`process_command()` 或 `enqueue_command()` 公开入口调用。

可运行实现见[命令插件教程](/tutorials/command-plugin/)。

## 阶段系统

当供给、需求、分配和状态变化必须在同一边界协调时，使用阶段系统。合同应声明：

- 运行 phase 与 cadence；
- 读取、写入和同边界可见性；
- 资源供给、预留请求和分配依赖；
- 可能发出的领域事件；
- 需要的随机流和 schema。

参伍按固定阶段运行这些系统，验证声明访问，完成确定性分配，并原子提交边界结果。
完整例子见[阶段边界与资源分配教程](/tutorials/phased-boundary/)。

## 文化系统 SDK

已正式发布的 `canwu-culture` SDK 是建立在 `canwu-society` 之上的面向开发者的编写层。参考内容包声明目标、
cohort、渠道、转移、制度和下游效果；SDK 校验预算并把定义编译成外部不可变、绑定内容哈希的文化执行计划。
运行时可完整恢复待处理关系集合（dirty set）、热目标、休眠调度和效果 cadence。退休目标经显式 society 同步后
不再参与目标相关热计算；增量聚合仍是后续工作。

上层应用的常规结算应使用 `settle_culture_society_boundary`。它只针对 active、到期 dormant 和显式观测目标准备
runtime delta，并且只更新生命周期发生变化的目标所对应的 society binding。完整的
`synchronize_society_lifecycle` 扫描只用于加载修复和显式维护检查点。

文化目标有 `Active`、`Dormant` 和 `Retired` 三种状态。休眠目标会离开文化热索引并保留重新激活描述；
退休目标会在同步时释放动态社会状态，同时保留墓碑和历史证据。重新激活必须显式且绑定代际；规范化输入适配器仍待实现。
详见[文化和法律制度系统](/architecture/culture-law/)。

## 法律制度化 SDK

实验性的 `canwu-law` 把法律编写定义编译成确定性计划，并提供法域关系、制度席位、冻结程序、逐席参与、
决策 outbox、待处理法律意图、不可变法律渊源与法律版本、稳定规则、案件裁决、适用和承继运行时。
作者必须在 `ClauseDefinition` 显式声明规范模态，并在 `LegalProposal` 区分法律权限、瑕疵、效力与精确来源；
内核命令授权不等于世界内法律有效。权利与资格条款还必须声明 holder、duty bearer、subject matter、standing 和 remedy 关系。
授权命令只能追加待处理意图；规范化的 `LegalMutation` 和 pending-intent ingress 由事件驱动插件在一个
`DomainDeltaProposal` 中重新校验，并用精确 record version 原子更新聚合。crate 的三阶段 outbox 适配器会先
持久化预期 revision，再结算 decision ingress，最后用持久化决策日志证明 controller 与 ticket-open 都已接受，
且当前票据与草案精确绑定；该证明不依赖保留 ingress payload。角色上下文由有界的持有者 `KnowledgeQuery` 结果生成。

开放程序、截止时间、最新参与、已分发 outbox、到期版本、决策结果和 dirty rule 都有持久化索引。适用性查询必须指定法律秩序
分区和精确编译 profile；承继按有界 reception scope 与规则前缀匹配，不会默认继受整个前法秩序。文化退休引用精确目标代际：作为制定证据的文化可退休且不会删除既有法律，
而仍有效的 `LiveLevel` 依赖会阻止退休；只有法律自身的复核、到期、废止或承继操作能改变其效力。
退休是有界维护操作：v1 聚合的依赖证明超过 `max_retirement_dependency_records` 条外层记录时，会在 mutation 前失败关闭。
详见[文化和法律制度系统](/architecture/culture-law/)。

## 财政模拟扩展

`canwu-fiscal` 是通用财政程序扩展：它负责法规、地区采纳、核算、减免、执行授权、审计和
持有人相对知识报告，但不拥有银粮余额、价格或运输。历史内容由独立参考内容包编译成不可变目录；
年份只产生时期与改革候选，不会自动实施改革。真实资源操作完成后，上层适配器必须提交引用
精确类型化结果版本的财政执行凭证。完整设计与三个可运行起点见
[明代财政案例](/tutorials/cases/ming-fiscal/)。

## 生命周期规则

- 在依赖插件的命令、场景验证或加载发生前注册插件。
- 从存档恢复或重放时提供相同插件集合。
- 不要让插件持有实时运行时引用或绕过 ingress 修改状态。
- 把 semantic hash 的变化视为可执行语义变化，并配套迁移或新版本。
- 应用层只通过 `canwu-api` 使用这些合同。

在实现前，先阅读[架构中的五个边界](/architecture/#五条架构边界)，再从最接近需求的公开示例开始。
