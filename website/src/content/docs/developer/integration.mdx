Canwu 是无头仿真内核。窗口、地图、网络、输入、AI 调度和帧循环都由主机程序负责；
Canwu 负责权威状态、验证、确定性时间、事件和证据。

## 添加依赖

Canwu 0.4.0 需要 Rust 1.88 或更新版本。应用代码应只依赖公开 facade：

```toml
[dependencies]
canwu-api = "0.4.0"
```

如果应用会长期保存 Canwu 快照，请固定精确版本，并把版本升级与存档迁移一起处理：

```toml
canwu-api = "=0.4.0"
```

不要直接依赖 `canwu-sim`、`canwu-world` 或其他实现 crate。它们可被 Cargo 解析，
但不是应用代码的独立兼容性表面。

## 最小主机流程

```rust
use canwu_api::{Canwu, SemanticAction, SimDuration};

let mut canwu = Canwu::demo(35)?;
let ids = Canwu::demo_ids();

canwu.act(
    ids.commander,
    SemanticAction::MoveArmy {
        army: ids.army,
        destination: ids.eastern_territory,
    },
)?;

let events = canwu.advance(SimDuration::days(1))?;
# Ok::<(), canwu_api::CanwuError>(())
```

真实应用通常用 `Canwu::new(seed, scenario)` 创建自己的场景；`Canwu::demo()` 只用于示例和原型。

## 选择写入入口

| 入口 | 适用场景 |
| --- | --- |
| `act(actor, SemanticAction)` | UI、智能体或工具希望使用面向能力的语义动作 |
| `submit(CommandEnvelope)` | 主机已经持有明确的类型化命令与发行者身份 |
| `process_command(CommandRequest)` | 外部服务需要带请求标识、重试和结果记录的规范化命令入口 |
| `enqueue_command(...)` | 命令必须在未来的模拟时间按优先级进入 |

无论选择哪种入口，主机都不应取得可变世界引用。Canwu 验证权限、前置条件和请求，
然后记录被接受或拒绝的结果。

## 驱动时间

<Steps>
1. 主机读取墙钟、回合输入或研究任务进度。
2. 主机按自己的速度策略把它转换为 `SimDuration`。
3. 普通事件驱动场景调用 `advance()`；使用日结、回合结算等阶段系统时调用 `advance_canonical()` 或显式 `settle_boundary()`。
4. 从返回的事件、边界回执或新的只读快照刷新表现层。
</Steps>

不要把浮点帧间隔直接写入权威状态。连续渲染程序应保留主机侧余数和表现插值；
完整模式见[连续时间游戏循环教程](/tutorials/continuous-game-loop/)。
