参伍是无界面历史模拟引擎。窗口、地图、网络、输入、AI 调度和帧循环由上层应用负责。
参伍负责通用权威状态、验证、确定性时间、事件和证据；具体世界模型与命令属于应用选择的领域整合。

## 添加依赖

当前 `main` 分支需要 Rust 1.88 或更新版本。下面的配置适合试用当前开发版本：应用依赖对外 API，并显式选择领域整合。

```toml
[dependencies]
canwu-api = { git = "https://github.com/PeiyuanQi/canwu", branch = "main" }
canwu-reference-world = { git = "https://github.com/PeiyuanQi/canwu", branch = "main" }
```

`canwu-reference-world` 是可替换的起步整合，不是引擎基础层。旧 `canwu-world` crate 已退役；不要依赖 `canwu-sim` 或其他运行时实现 crate。

进入生产环境前，应固定已发布的精确版本或 Git 修订，并把每次引擎升级与显式存档迁移一起处理。

## 最小接入流程

```rust
use canwu_api::{Canwu, CommandRequest, CommandRequestId, EntityRef, Issuer, SimDuration};
use canwu_reference_world::{
    MovementCommand, ReferenceWorldPlugin, demo_scenario, order_movement,
    snapshot as reference_snapshot,
};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let (scenario, ids) = demo_scenario()?;
    let plugin = ReferenceWorldPlugin;
    let mut canwu = Canwu::new_with_plugins(35, scenario, &[&plugin])?;

    let command = order_movement(
        Issuer::Actor(ids.commander),
        &MovementCommand {
            subject: EntityRef::Army(ids.army),
            destination: ids.eastern_territory,
            cargo: Vec::new(),
        },
    )?
    .at_time(canwu.time());
    canwu.enqueue_command(
        canwu.time(),
        0,
        CommandRequest::new(CommandRequestId::new(1), canwu.revision(), command),
    )?;
    canwu.advance_canonical(SimDuration::hours(19))?;

    println!(
        "army_location={}",
        reference_snapshot(&canwu)?
            .army(ids.army)
            .expect("demo army exists")
            .location
    );
    Ok(())
}
```

在仓库根目录运行完整示例：

```shell
cargo run -p canwu-reference-world --example starter
```

示例中的 `35` 是确定性的演示种子，`0` 是命令优先级，19 小时会跨过参考移动系统的结算时间点。
程序会打印军队的最终位置；完整 `starter` 示例还会验证存档、派生分支和精确重放。
真实应用通常构建自己的 `Scenario` 与插件，`demo_scenario()` 只是可运行模板。

## 选择写入入口

| 入口 | 适用场景 |
| --- | --- |
| `submit(CommandEnvelope)` | 调用方已持有类型化领域命令与发令者身份 |
| `process_command(CommandRequest)` | 外部服务需要请求标识、修订校验和结果记录 |
| `enqueue_command(...)` | 命令必须在指定模拟时间按优先级进入 |

领域整合负责把 UI 或智能体意图转成类型化领域命令。无论选择哪个入口，调用方都不会取得可变世界引用。

## 撤回排队的插件输入

用 `enqueue_plugin_ingress` 排队的插件输入，只要仍在队列中且尚未到期，就可以撤回：

```rust
let queued = canwu.enqueue_plugin_ingress(request)?;
// 玩家在命令到期前撤回了它。
canwu.cancel_plugin_ingress(queued.ingress_id, "withdrawn by player")?;
```

只有签发者可以撤回。上层应用用 `cancel_plugin_ingress` 撤回自己提交的公开数据包；内部数据包类型需要用 `cancel_permitted_plugin_ingress` 并出示所属插件的注册许可，该许可也覆盖该插件自己安排的输入；插件的边界系统用 `BoundaryDirective::CancelPluginIngress` 撤回本插件安排的输入。撤回会作为独立的 `IngressPayload::PluginCancellation` 记录写入日志，记下被撤回的输入、`IngressCancellationAuthority` 和不超过 1,024 字节的原因。被撤回的输入永远不会被准入，也不会发生回滚。已经到期、已准入、已归档或已撤回的输入会以 `LateIngress` 失败；其他签发者的输入以 `InvalidAuthority` 失败；未知 ID 以 `EvidenceUnavailable` 失败。快照、检查点日志和精确重放都会保留这次撤回。

## 已无法行事的人物

自 0.12.0 起，运行时为每个人物保存人物可用性（`PersonAvailability`）：生存状态（`Alive`、`Dead`、`Missing`）与人身状态（`Free`、`Detained`、`Hostage`、`Captive`、`Hiding`、`Exile`）。人物何时死亡、被俘或获释由上层应用决定，并由声明了 `StateKey::core_person_availability()` 的第 7 或第 10 阶段边界系统返回 `BoundaryDirective::SetPersonAvailability` 来记录。用 `canwu.person_availability(person)` 读取；`None` 表示存活且自由。

未存活、被拘押或被俘的人物不可用：

- 若命令的签发者、决策角色或机构责任角色不可用，命令准入会以 `IssuerUnavailable` 拒绝；带请求标识的命令会记录为持久化拒绝；
- 若决策票据的人物决策者（`DecisionMakerUnavailable`）或其控制者的权限人物（`IssuerUnavailable`）不可用，就不能开启、准备或结算该票据；
- 在使人物变为不可用的边界结束时，以该人物为决策者的未关闭票据会以 `decision_maker_unavailable` 取消，由其担任控制者权限人物的未关闭票据会以 `controller_authority_unavailable` 取消。

人质、藏匿和流亡状态默认仍可准入；更严格的规则由你自己的系统实现。已取消的票据不会被改派。若只是控制者的权限人物变为不可用，要继续这项决策，请为可用的控制者开启新票据，并把 `parent_ticket` 设为已取消的票据。决策者仍不可用时，不能为其开启新票据。

## 驱动时间

<Steps>
1. 上层应用读取现实时间、回合输入或研究任务进度。
2. 上层应用按自己的速度策略把它转换为 `SimDuration`。
3. 普通事件驱动场景调用 `advance()`；含日结、回合结算等边界系统时调用 `advance_canonical()` 或显式 `settle_boundary()`。
4. 从事件、边界回执或领域整合生成的只读投影刷新表现层。
</Steps>

不要把浮点帧间隔直接写入权威状态。完整模式见[连续时间游戏循环教程](/tutorials/continuous-game-loop/)。
