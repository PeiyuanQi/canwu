参伍存档不只是一个序列化的世界对象。可恢复状态还包括命令、事件、结算边界、随机证据、
插件语义环境和状态承诺。先确定恢复目标，再选择相应接口。

## 先选择恢复目标

| 目标 | 使用 | 上层应用责任 |
| --- | --- | --- |
| 普通存档或服务重启 | `snapshot_json()` 与 `from_snapshot_json_with_plugins()` | 保存完整快照，并在加载时提供相同插件集合 |
| 长期运行的紧凑存储 | `checkpoint_journal_json()` | 保存经验证的检查点及其后连续日志 |
| 审计或精确重建 | `replay_journal()` 与 `replay_from_journal()` | 保存完整日志和匹配的插件语义环境 |
| 向外部系统发送副作用 | `outbox_entries()` | 至少投递一次，并按 `delivery_id` 去重和记录确认状态 |
| 从同一起点尝试另一组输入 | `fork()` | 把结果当作新的平行现实，不与精确重放混淆 |

## 版本与格式合同

截至 2026 年 9 月 27 日，工作区版本为 `0.13.0`，快照格式为 8。精确的
`engine_version` 仍属于存档合同，因此 0.12.0 及更早版本的快照不能直接用于 0.13.0 运行。
0.13.0 新增转移清单、评估轨迹、席位继任、动用授权、带运力池的 `canwu-movement` 扩展、受托承运人与承运人扣押、真伪判定、法律程序的加权阶段、表决单元阶段与征询阶段、文化结算插件、cohort 人口校准、政策压力来源以及外部传播来源；资源、通信、信息、社会、技术和法律插件的语义标识随之变化，`TRANSPORT_SEMANTIC_VERSION` 变为 `canwu-transport.v5`，快照格式仍为 8。详见下方 [0.13.0](#0130) 一节。本地引擎代码的更新不会改变下游应用固定的注册表依赖版本。
模拟内核不会静默迁移旧快照，也不能只修改格式号来伪装兼容。

需要长期保存状态的应用应固定已发布的精确版本或 Git 修订。跨版本保留历史时，
由上层应用运行显式导出/导入流程，或保留能够读取旧数据的旧引擎。

## 快照保存与恢复（节选）

```rust
use canwu_api::Canwu;
use canwu_reference_world::{ReferenceWorldPlugin, demo_scenario};

let (scenario, _) = demo_scenario()?;
let plugin = ReferenceWorldPlugin;
let canwu = Canwu::new_with_plugins(35, scenario, &[&plugin])?;

let json = canwu.snapshot_json()?;
let restored = Canwu::from_snapshot_json_with_plugins(&json, &[&plugin])?;
assert_eq!(restored.checkpoint_hash(), canwu.checkpoint_hash());
```

这段代码是接入节选。可以运行完整示例验证快照、派生分支和精确重放：

```shell
cargo run -p canwu-reference-world --example starter
```

插件名称、版本和语义哈希都是插件语义环境的一部分。只要存档包含插件领域记录，
加载和重放就必须提供兼容的插件集合。

## 检查点日志与精确重放

检查点日志把一个经验证的检查点与之后的连续证据组合起来，适合长期运行。
精确重放则从日志内的初始场景、输入和证据重建同一模拟运行：

```rust
let checkpoint_journal = canwu.checkpoint_journal_json()?;
let journal = canwu.replay_journal();
let replayed = Canwu::replay_from_journal(&[&plugin], &journal)?;

assert!(!checkpoint_journal.is_empty());
assert_eq!(replayed.checkpoint_hash(), canwu.checkpoint_hash());
```

`replay_from_journal()` 不接受调用方另传的场景。运行身份、引擎版本、插件语义环境和
已记录证据必须匹配；重放使用已记录结果，不重新询问外部服务或重新发送副作用。

## 外发项的四条规则

1. 把 `delivery_id`、投递状态和确认状态保存在上层应用自己的持久化存储中。
2. 按至少一次语义投递；超时或重启后可以安全重试。
3. 接收方按 `delivery_id` 去重，不能依赖网络调用只发生一次。
4. 精确重放会生成相同外发项身份，但不会代表上层应用再次投递。

封存证据后，调用方还必须保存返回的 `EvidenceJournalSegment` 及其外发确认状态。
压缩或封存不等于已经投递或确认。

## 高级存储与归档

只有在快照大小或热历史成为实际问题后，才需要分页检查点、`StatePageProvider`、
决策历史归档或插件归档参与者。此时上层应用必须：

- 按内容标识保存并返回精确页面字节；缺页必须明确失败，不能伪装成空数据；
- 保存检查点要求的连续日志前缀和归档保留根；
- 让每个插件恢复相同的归档合同与语义哈希；
- 在删除冷数据前，根据已提交根完成可达性验证。

完整的格式号、分页合同与归档不变量见仓库中的
[版本与持久化合同](https://github.com/PeiyuanQi/canwu/blob/main/docs/versioning.md)。

## 平行现实

`fork()` 从当前点创建独立模拟。它适合比较另一组命令、策略或研究假设；
每个派生分支仍通过正常命令与时间入口推进。它不是精确重放，因为后续输入可以不同。

## 上线前检查

- 固定引擎版本和插件语义环境。
- 完成一次保存、进程重启、加载和哈希比较。
- 完成一次精确重放，并比较最终检查点哈希。
- 模拟外发投递超时，确认按 `delivery_id` 重试不会重复产生外部效果。
- 为版本升级写明显式导出、迁移或放弃旧存档的政策。


## 0.13.0

Canwu 0.13.0 是次版本发布。新增合同都是增量能力，但新的枚举变体和结构体字段会破坏穷举匹配与结构体字面量，因此对使用它们的代码并非源码兼容。快照格式 8、承诺格式 4 和检查点/证据日志格式 4 保持不变；未使用新合同时，相关字段不会序列化。

- 快照新增 `pending_transition_manifests`；边界记录新增 `evaluation_traces`、`transition_manifests` 与 `transition_audits`，边界回执新增 `transition_audits`。从未登记转移清单、也未记录评估轨迹的运行，哈希与以前完全相同。
- 评估轨迹随边界记录一起封存和归档，并计入日志大小。运行配置的 `evaluation_limits` 取默认值时不会序列化，因此只有设置它时配置哈希才会变化。
- `canwu-movement` 把运行时保存在 `canwu.movement:runtime` 这一条领域记录中；文化结算插件新增 `canwu.culture:definition` 与 `canwu.culture:exposure-queue` 记录，society 插件新增 `canwu.society:ingress-queue`。
- 资源、通信、信息、社会、技术和法律插件的语义哈希变化；`MovementPlugin` 与 `CultureBoundaryPlugin` 是新的插件标识，`CulturePlugin`、生产和财政插件保持不变，现有法律计划的编码和内容哈希也不变。`TRANSPORT_SEMANTIC_VERSION` 变为 `canwu-transport.v5`。
- 以下修复会改变现有运行的结果：实时生产完成现在可以结算产出；`AmendDemand` 不能再修改需求的状态、拒绝原因或申请者；程序阶段不再接受选票时，席位工作会过期，迟到的席位回应记为拒绝；cohort 转移之后的 society 每日边界不再失败；快照恢复接受引用仅列于 `Scenario::entities` 中实体的初始记录。

0.12.0 的快照不能改标签，也不能直接加载到 0.13.0。请保留旧引擎，或运行显式导出流程。

## 0.12.0

Canwu 0.12.0 是次版本发布。新增合同都是增量能力，但新的枚举变体和结构体字段会破坏穷举匹配与结构体字面量，因此对使用它们的代码并非源码兼容。快照格式 8、承诺格式 4 和检查点/证据日志格式 4 保持不变；未使用新合同时，相关字段不会序列化，记录的编码和哈希与之前相同。

- 快照新增 `person_availability`、`created_persons` 人物创建登记表和人物计数器；边界记录新增人物可用性变更（以及因此取消的票据）和人物创建记录。
- 通过 `cancel_plugin_ingress`、`cancel_permitted_plugin_ingress` 或 `CancelPluginIngress` 撤回的插件输入，会以 `PluginCancellation` 记录保留在输入日志中。恢复时会在待处理队列中排除被撤回的输入，精确重放会重新应用该撤回。
- 决策票据和决策轨迹可以携带 `parent_ticket`、决策阶段与触发的前置规则；控制者可以携带随机平局决胜的启用标志。
- 上层应用自行提交、带随机抽样证据的决策输入会被拒绝，运行时和加载快照时都一样。
- 资源、生产和财政插件的语义哈希以及资源持有人报告的知识 schema 随之变化；`TRANSPORT_SEMANTIC_VERSION` 变为 `canwu-transport.v4`；通信插件的语义哈希不变。

0.11.1 的快照不能改标签，也不能直接加载到 0.12.0。请保留旧引擎，或运行显式导出流程。

## 0.11.1

Canwu 0.11.1 是补丁版本。完成租约由持有或准备状态释放时，会在验证前从有界到期索引移除相应授权；快照格式和公开类型形状保持不变。
