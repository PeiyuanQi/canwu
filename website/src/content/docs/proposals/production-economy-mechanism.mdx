## 结论

生产、消费、建设和军事补给应先由上层应用插件在对外 `canwu-api` 上实现。粮食、工厂、价格、军队和历史资源地图不应进入模拟内核。

Celestial Mandate 曾用固定的合成夹具在 Canwu 0.6 对外 API 上验证这条边界：上层应用插件可以完成确定性部分分配、同地消费、货物托管、损耗、到货验收、次边界军事消费、整次边界原子回滚、精确存档恢复、分支与重放和持有人相对报告，无需修改模拟内核。该历史夹具仍是架构证据，但不表示当前 API 版本；当前版本合同见[存档、重放与分支](/developer/persistence/)。夹具采用上层应用自有的固定类型化行程；组合参伍运输执行类型仍是后续可玩集成门槛。

这项证明支持继续采用上层应用扩展，但还不足以创建 `canwu-resource` 或 `canwu-production`。

## 所有权

- 模拟内核：命令准入、时间与阶段顺序、预留分配、声明式读写、原子提交、回滚、证据、可见性、存档和重放。
- 上层应用的资源层：资源定义、账户、需求、持久预留、转移和消费结算。
- 上层应用的运输适配器：货物余额、在途托管、损耗、接受、退回和目的地入账；`canwu-transport` 只负责移动执行、路线腿、容量和交付完成桥接。
- 上层应用的人口、生产和军事领域：形成需求并消费已接受的履约结果，不直接改写其他领域的库存。
- 历史内容：地点、资源、工艺、设施、制度、参数和来源；不能获得特权写入路径。

## 提取门槛

只有在两个独立的生命周期所有者或两个独立上层应用都重复证明同一套账户、预留、转移、运输投影和履约语义后，才考虑实验性资源扩展。生产扩展必须建立在该守恒层之上，并拥有版本化工艺、工单、在制品、质量、损耗、维护和设施生命周期。

大型动态分配、局部提案拒绝或新的模拟内核查询 API 都必须先有失败的对外 API 夹具；架构图本身不是扩展模拟内核能力的理由。

## 不进入模拟内核的内容

- 历史商品、矿点、农业日历和时代参数；
- 全国统一价格作为物理库存真相；
- 建筑等级、生产方式或科技解锁自动产生地方能力；
- 把路线可达当作预订、发运、到货或可消费；
- 把运输执行记录当作上层应用货物余额与损耗权威。

有关上层应用实现方法，请参阅[生产、资源与运输边界](/developer/production-economy/)。
