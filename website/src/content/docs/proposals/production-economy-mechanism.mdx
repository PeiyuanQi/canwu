本页记录生产、消费和军事补给在参伍中的位置及理由。当你在判断一条新的经济规则应放在自己的应用里、可选扩展里，还是模拟内核里时，可以参考本页。

## 结论

:::note[状态：已交付]
`canwu-resource` 与 `canwu-production` 作为建立在对外 `canwu-api` 之上的可选扩展发布，首次发布于 0.10.0。当前 API 见[生产、资源与运输的职责划分](/developer/production-economy/)。
:::

生产、消费和军事补给都作为 `canwu-api` 之上的可选扩展实现。粮食、工厂、价格、军队和历史资源地图放在扩展、内容包和上层应用中；模拟内核只保留通用的结算能力。

## 决定所依据的证据

1. **上层应用夹具。** 基于参伍开发的下游策略游戏 Celestial Mandate 最早在参伍 0.6 对外 API 上，用一个合成夹具检验了这条边界，只用上层应用自己的插件，没有改动内核。
2. **可运行的循环。** 可替换的 `canwu-economy-reference` 整合运行一个十四个月的粮食循环，使用真实的路线规划和运输类型（`cargo run -p canwu-economy-reference --example grain_loop`）。
3. **两个独立消费者。** `canwu-production` 与军事补给参考消费者（`canwu-force-supply-reference`）各自拥有不同的生命周期，却共用同一套账户、资源预留、资源分配、转移和履约。同一生命周期有两个独立使用方，正是提取共享扩展的前提。
4. **稀缺度与价格压力读取。** 参考整合提供有证据支撑的本地稀缺度投影和价格压力投影。它们是只读模型，完整的市场模拟不在这次交付范围内。

这个前提满足后，`canwu-resource` 与 `canwu-production` 成为可发布的可选扩展；`canwu-force-supply-reference` 与 `canwu-economy-reference` 仍是不发布、可替换的整合包。

## 所有权

| 负责方 | 负责内容 |
| --- | --- |
| 模拟内核 | 准入、时间与阶段顺序、资源预留分配、声明式读写、原子提交、回滚、证据、可见性、存档与重放 |
| `canwu-resource` | 资源定义、单位、账户、受保护存量底线、需求、资源预留、资源分配、转移、消费、损耗和履约 |
| `canwu-production` | 工艺、生产地点、设施、产能、工单、在制品、执行、项目和产出结算 |
| `canwu-transport` 与 `canwu-movement` | 行程、路段、保管交接和运力记录（`canwu-transport`），以及它们的生命周期：移动命令、路段结算和运力池（`canwu-movement`）。在途货物余额、损耗、验收、退回和目的地入账仍由 `canwu-resource` 负责。 |
| 人口、生产和军事领域 | 形成需求并使用精确的履约结果，各自只写自己的状态 |
| 历史内容 | 地点、矿点、工艺、设施、制度、参数和来源，没有特殊的写入路径 |

生产扩展建立在守恒资源层之上，负责版本化的工艺、工单、在制品、维护和设施，产出交回 `canwu-resource` 入账。

## 什么条件下才能移入内核

这次交付没有新增模拟内核查询 API，也没有把领域规则移入内核。将来的完整市场、货币、产权、通用建设或战斗系统，也需要同样的证明：有多个独立消费者共用其生命周期，并有一个不改内核就无法通过的对外 API 夹具。只有架构图是不够的。

## 不进入模拟内核的内容

- 历史商品、矿点、农业日历和时代参数。
- 被视为实物库存真值的全国统一价格。
- 由建筑等级、生产方式或科技解锁自动产生的地方能力。
- 被视为预订、出发、到达或可用交付的可达路线。
- 被视为货物余额与损耗依据的运输执行记录。
