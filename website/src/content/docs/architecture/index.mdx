Canwu 是一个不负责渲染和用户界面的历史模拟内核（headless core）。客户端可以是游戏、研究工具、调试界面或智能体，但它们都通过同一组公开边界访问模拟，而不是取得实时可变世界的引用。

## Format 6 与三种模拟粒度

0.6 在 1.0 之前采用 clean break：快照和 `ReplayJournal` 必须自带声明式运行身份、初始场景、commitment、authority root 与完整证据；内核不自动加载 format-4/5 存档。`SimulationGranularity` 只定义领域无关的 `aggregate`、`group`、`actor` 三层。Celestial Mandate 可在自己的参考整合包中将它们映射为 Population、Special Group、Character；Southern Ming 与 WWII 是 CM 内容与规则整合，不是参伍内核模块。

## 从客户端到内核

| 层 | 责任 | 公开承诺 |
| --- | --- | --- |
| 客户端 | 地图、渲染、输入、研究工作流与智能体循环 | 自由选择界面，不拥有权威状态 |
| `canwu-api` | 程序对外 API、命令、领域记录、事件、快照与重演 | 通过验证后的公开入口工作 |
| `canwu-sim` | 调度、插件、结算、持久化与重演 | 唯一持有实时可变模拟状态 |
| 基础与模型 crate | ID、时间、事件、决策与角色知识 | 提供可序列化、跨平台的引擎契约 |

## 五条架构边界

1. **命令边界**：外部改变必须进入验证过的引擎命令、领域插件命令或规范化输入；客户端不能直接改写状态。
2. **读取边界**：对外 API 返回通用实体、领域记录和证据；领域整合生成脱离运行时的投影，`CanwuViewer` 限定角色知识。
3. **确定性边界**：时间、队列、插件执行顺序、资源分配和随机流都有明确的规范排序。
4. **插件边界**：插件先声明读取、写入、阶段、资源和随机流，再由内核校验并执行。
5. **证据边界**：命令、事件、结算、随机抽样、状态变化和哈希共同组成可检查、可重演的记录。

## 一次行动如何穿过系统

<Steps>
1. 客户端或领域整合通过 `canwu-api` 提交类型化命令；内核验证权限、前置条件、修订版本和请求身份。
2. 接受的命令产生带因果引用的事件，并按可表示的模拟时间安排后续工作。
3. 到达结算边界后，内核切出准入集合和不可变边界快照，按固定阶段运行插件系统。
4. 系统提出资源申请、状态变化、领域记录和事件；内核验证声明范围并原子提交。
5. 结算记录保存事件、随机抽样、分配、变化、生产者和哈希，客户端再读取快照或角色视角的观察结果。
</Steps>

## 工作区 crate

| crate | 核心职责 |
| --- | --- |
| `canwu-core` | 类型化 ID、确定性随机工具和模式元数据 |
| `canwu-time` | 历史时间戳与经过检查的时长运算 |
| `canwu-decision` | 决策票据、确定性求值、控制者与决策策略 SDK |
| `canwu-event` | 通用事件信封、因果来源、受众和结构化事件记录 |
| `canwu-reference-world` | 可替换的示例实体、移动插件、脱离式投影、路由适配器与入门示例 |
| `canwu-knowledge` | 角色知识、来源、可信度与信息时效 |
| `canwu-routing` | 确定性时变路由原语 |
| `canwu-transport` | 运输执行、行程修订、交接、预订与 saga 原语 |
| `canwu-sim` | 私有运行时、调度、插件和结算 |
| `canwu-api` | 通用程序对外 API、规范命令、领域记录、证据与重演 |
| `canwu-information` | 实验性权威信息生命周期扩展 |
| `canwu-correspondence` | 实验性通信模拟领域扩展与模拟插件 |
| `canwu-society` | 实验性社会传播模拟模块 |
| `canwu-culture` | 实验性文化编写、编译与生命周期扩展 |
| `canwu-technology` | 实验性、证据驱动的通用技术模拟扩展 |
| `canwu-history-research` | 可选的下游历史研究评估插件 |
| `canwu-debug` | 使用公开 API 与参考世界整合包的参考客户端 |

实验性的 `canwu-culture` 文化系统 SDK 建立在 `canwu-society` 之上，不会进入模拟内核。
它把版本化内容编译成外部不可变、绑定内容哈希的执行计划，校验数量与展开后的扇出预算，并提供待处理关系集合
和热目标索引。完整状态记录可以恢复生命周期调度、热/脏索引和效果 cadence。休眠目标离开文化热索引；
主机显式同步 society 后会停用其由文化计划编译的转移规则。退休目标还会释放目标相关的动态社会状态并保留历史证据。
边界系统注册、规范化信号准入和增量聚合仍是后续工作。
详见[文化系统编写与生命周期设计](/architecture/#文化系统编写与生命周期)。

## 文化系统编写与生命周期

这是面向开发者的扩展层。参考内容包声明目标、cohort、渠道、转移、制度和下游效果绑定；编译器
生成由社会传播运行时消费的确定性计划。跨扩展输入和输出使用有界的下一边界批次，不使用同步回调。

文化目标在配置的静默窗口内没有参与人口或准入工作后进入 `Dormant`。显式调用 society 生命周期同步后，
休眠目标停止运行由文化计划编译的转移规则；进入 `Retired` 后还会释放可重建分布、空的文化 binding 与派生状态，
但保留紧凑墓碑以及历史领域记录、事件、角色知识和归档引用。推荐的组合 API 先准备 runtime delta，只有生命周期
发生变化时才暂存 society；活依赖会让退休失败且两边都不提交。主机仍须在同一权威边界中持久化结果与生命周期转移。
显式重新激活会创建新一代目标，不会改写旧历史。

计划中的 `canwu-law` 法律制度化扩展会消费文化信号，通过 `DecisionTicket`、授权命令和版本化领域记录
落盘法律规则；文化系统不能直接写法律状态。详见[法律制度化设计](/architecture/#法律制度化设计)。

## 法律制度化设计

法律扩展把文化信号当作有证据的社会输入，而不是法律权限。它通过法律提案、机构程序和控制者绑定的
`DecisionTicket` 生成选项；只有经过验证的规范化法律命令才能提交 `LawVersion`。已经制定的法律
不会因文化目标 `Retired` 自动消失；动态支持度结束只触发法律扩展自己的复核、到期或废止规则。
完整契约见[法律制度化框架](https://github.com/PeiyuanQi/canwu/blob/main/docs/proposals/legal-institutionalization-framework.md)。

## 从领域扩展到可运行套件

参伍不仅提供内核契约。通用领域扩展提供可复用机制，参考内容包提供可
替换的领域数据，参考整合包把这些能力接入一个小型世界，入门套件则把
它们组合成开发者可以直接运行和改造的纵向切片。这些层都在内核之上，
不会把某个历史世界写入 `canwu-core`。

`canwu-correspondence` 在所有权上是模拟领域扩展：它负责通信需求、地址解析、
接受的路径、遇灾与截取政策，以及跨机制证据；在执行形式上，它同时是一个
`SimulationPlugin`，通过权威命令、规范化输入（canonical ingress）和边界系统接入运行时。
它依赖 `canwu-api` 与 `canwu-information`，反向依赖不存在，因此不会形成依赖环。

参考内容包是数据，不是新的求解器；参考整合包必须使用公开 API，并且
可以被另一种世界或经济模型替换；入门套件必须展示场景创建、命令、结算、

设计成只有一个固定 Demo 的特殊路径。
