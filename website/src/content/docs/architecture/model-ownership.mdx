这次审计回答的不是“哪个 crate 行数太少”，而是“哪个层应该拥有这项语义”。结论是：**不应全面合并 crate**。具体事件载荷已从通用 `EventKind` 中迁出，示例世界也先迁入 `canwu-reference-world`，然后才删除失去独立职责的旧包边界。

<Aside type="note" title="迁移状态">
所有权迁移现已完成。`canwu-reference-world` 拥有示例模型、移动插件、脱离式投影和路由适配器；旧源码包和依赖边已经删除。Format 8 快照自带规范实体注册与初始场景，Format 8 以前的存档由内核拒绝，不进行隐式迁移。
</Aside>

## 一条所有权规则

通用引擎 crate 拥有确定性模拟契约；参考整合包拥有军队、政府、领土、人物、信件等具体世界实体，以及描述它们领域行为的事件载荷。

Format 8 对跨插件维护也遵守同一规则：内核只验证参与者集合、版本、预算与原子提交，绝不替插件生成领域语义。每个参与者只能修改由本插件拥有的领域 schema；目标记录的所有者还必须提交对该目标记录的精确修改。插件描述符固定依赖解析器注册，调用方不能通过漏报参与者绕过检查。

因此两个候选 crate 的结论并不相同：

| crate | 审计结论 |
| --- | --- |
| 已退役的 `canwu-world` | 具体模型现由 `canwu-reference-world` 拥有；当前 `WorldSnapshot` 仅作为参考整合与运行时投影保留。 |
| `canwu-event` | 现在只包含通用事件契约和结构化事件记录。具体载荷已经迁出；剩余通用类型是否并入 `canwu-sim`，必须等独立消费情况明确后再决定。 |

## `canwu-world` 的 12 个公开类型

| 公开类型 | 分类 | 目标归属 |
| --- | --- | --- |
| `MapPoint` | 具体地图与展示模型 | 参考世界整合包 |
| `Person` | 具体人物模型 | 参考移动/世界整合包 |
| `PersonTransitState` | 具体人物旅行状态 | 随 `Person` 迁移 |
| `LetterStatus` | 具体信件保管和交付生命周期 | 参考信息/物流整合包 |
| `LetterCargo` | 具体信件正文、收发者、位置和保管状态 | 参考信息/物流整合包 |
| `Government` | 具体政府与首都模型 | 参考政治/世界整合包 |
| `Territory` | 具体领土、控制者和坐标模型 | 参考拓扑/世界整合包 |
| `Route` | 具体领土间双向路线 | 参考拓扑整合包，并转换为路由自身的 `PlanningSnapshot` |
| `TransitState` | 具体军队旅行状态 | 参考移动/世界整合包 |
| `Army` | 具体军队、指挥官、兵力和士气模型 | 参考移动/世界整合包 |
| `WorldSnapshot` | 只包含上述具体实体的参考投影 | 由参考整合包提供给需要它的上层应用；不承担旧存档迁移 |
| `WorldDiff` | 只追踪军队、人物、领土和信件 ID 的参考差异 | 由参考整合包提供；通用内核使用边界变化证据 |

`canwu-routing` 不拥有这个世界。求解器只接收通用 `PlanningSnapshot`；`WorldSnapshot` 转换现已迁入 `canwu-reference-world`。

## `canwu-event` 的 4 个公开类型

| 公开类型 | 分类 | 目标归属 |
| --- | --- | --- |
| `CauseRef` | 通用引擎契约 | 保留命令、父事件、边界和系统因果语义及序列化兼容性 |
| `EventAudience` | 通用引擎契约 | 保留默认私有、角色范围和可重放的可见性语义 |
| `SimEvent` | 通用事件信封 | 保留身份、时间、影响对象、摘要、因果和相关标识语义 |
| `EventKind` | 通用类型标签和扁平化结构字段记录 | 保持旧 JSON 线形状；领域所有者在本 crate 外定义强类型载荷，并通过通用编码与解码 API 使用 |

移动、军队到达、人物旅行、信件交付、报告派发、知识和调试字段等强类型载荷已不再是 `canwu-event` 的公开变体。当前参考运行时私有兼容载荷仍负责严格校验旧标签和字段；它们会随相应世界、知识或调试整合继续迁移。插件事件通过 `plugin_identity` 提供兼容命名空间身份。

## 0.13.0 之后的领域归属

同一条规则也决定了下游大战略缺口集在 0.12.0 与 0.13.0 交付的各项合同归属何处：必须确定、权威且可重放的内容由引擎拥有；时代内容和应用自身的权限仍由应用负责。

| 关注点 | 所有者 | 应用边界 |
| --- | --- | --- |
| 人物生存与人身状态、运行时创建人物、撤回排队输入 | `canwu-sim` 核心状态与指令（0.12.0） | 人物何时死亡、被俘、获释或出现；撤回哪些输入 |
| 多所有者条件转移 | `canwu-sim` 转移清单、第 10 阶段暂存与第 11 阶段审计 | 每次转移的参与者、预期版本和含义 |
| 规则评估证据 | `canwu-core` 记录、`canwu-sim` 边界证据、`canwu-api` 视图读取 | 规则 ID 及各项的含义 |
| 决策谱系与席位继任 | `canwu-decision` 票据与控制者绑定 | 谁占据席位、继任者何时接任 |
| 委托动用资源 | `canwu-resource` 动用授权与 `Granted` 来源策略 | 谁可以授权给谁，以及权限证据记录 |
| 移动生命周期与运力池 | `canwu-movement` 运行时记录与插件；`canwu-transport` 记录与纯函数分配 | 事故、危险、敌对行为及其随机抽样，以及权限依据记录 |
| 受托承运人与承运人扣押 | `canwu-correspondence` | 委托背后的关系，以及把扣押消息转告发送者 |
| 真伪判定 | `canwu-information` 解读记录 | 伪造被识破的概率 |
| 加权、表决单元与征询程序阶段 | `canwu-law` 编译后的程序 | 席位权重、表决单元和平局规则的选择 |
| 引擎内文化结算 | `canwu-culture` 的 `CultureBoundaryPlugin` 结算生命周期并产生变化；`canwu-society` 仍是 `canwu.society:state` 的唯一写入者 | 接触信号和文化定义 |
| 政策压力来源与 cohort 人口校准 | `canwu-society` | 人口校准所引用的外部存量记录 |
| 外部传播来源 | `canwu-technology` | 所引用的内容记录及其声明的可靠度 |
| 财政归档、观察者上限、批量消费、生产上限 | 尚未发布，属于延后的系列项 | — |

有两个名字容易混淆。参考世界的移动插件通过 `OrderMovement` 移动示例世界中的军队和人物，是可以替换的示例代码；`canwu-movement` 是面向 `canwu-transport` 记录的通用移动生命周期扩展，并不了解参考世界。

## 为什么不能直接合并

- 把 `canwu-world` 并入 `canwu-core` 会把一种历史世界观变成基础依赖。
- 现在立即把 `canwu-event` 并入 `canwu-sim` 仍会扩大持久化变更面；是否合并要由剩余通用契约的独立消费情况决定。
- 新建 `canwu-model` 只会合并名字，不会明确职责。
- 合并 `canwu-api` 与 `canwu-sim` 会破坏对外 API 和私有运行时的边界。

## 安全迁移顺序

<Steps>
1. 已固定代表性的 JSON 存档、事件日志、`canwu-api` 调用与精确重放结果。
2. 已把 `EventKind` 改为通用结构化记录，并在不改变旧 JSON 形状的前提下迁出具体公开变体；完整的跨整合包命名空间与载荷版本仍是后续契约。
3. `canwu-reference-world` 已通过对外 API 接管具体实体、移动行为、脱离式投影和路由转换。
4. Format 7 起，快照自描述实体注册与初始场景（当前 Format 8 沿用）；可运行入门示例证明保存、加载、派生分支与精确重放。
5. `canwu-world` 在普通消费者归零后已退役；`canwu-event` 的独立边界仍留待单独决策。
</Steps>

## 实施完成门槛

Format 7 起拒绝 Format 2–6 存档和日志；Format 8 保留这些迁移契约并进一步拒绝 Format 7 持久化数据。因果、相关标识、受众、影响对象和承诺校验必须保持确定且默认拒绝；路由 crate 必须不再依赖示例世界；至少一个可运行入门套件必须证明保存、加载、派生分支和精确重放；还需要第二种整合或测试夹具证明通用引擎没有暗中依赖第一种历史模型。

完整的逐类型理由、依赖证据和门槛记录在仓库中的规范审计文档。
