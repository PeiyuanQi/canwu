这是一页关于两个可选领域扩展的统一架构说明：已正式发布的 `canwu-culture` 文化系统 SDK，
以及已实现的实验性 `canwu-law` 法律制度化扩展。它们都建立在公开 API 和社会传播模拟模块之上，
但不把历史文化、法律语义或某个具体时代写入参伍的模拟内核。

核心原则很简单：**文化系统产生有证据的社会信号，法律系统通过经授权的制度程序解释这些信号并提交法律版本。**
文化支持度不是法律权限，也不会自动变成一条法令。

## 所有权与分层

`canwu-culture` 是位于 `canwu-society` 之上的编写和编译扩展。它接收版本化的参考内容，
校验数量、展开扇出、内存、状态和边界工作预算，然后生成外部不可变、绑定内容哈希的文化执行计划。
`canwu-society` 仍负责稀疏人口分布、社会影响边、组织拓扑、制度输入和角色相对投影。

`canwu-law` 位于文化信号的下游，拥有辖区、法律机构、程序、法律提案、已制定规则、
生效时间、修订、废止、失效和法律解释。政治、选举、行政、教育、司法与执行扩展只拥有各自的过程，
并在声明的结算边界中消费已制定法律。

```text
参考内容包
    |
    v
canwu-culture 编写与编译器
    |
    v
canwu-society 稀疏社会运行时
    |
    +--> CulturalSignalBatch（有界、带因果、下一边界准入）
                |
                v
         canwu-law（法律提案 -> 程序 -> LawVersion）
                |
                v
      政治 / 选举 / 行政 / 教育 / 司法 / 执行适配器
```

依赖方向是单向的：信息和通信扩展可以给文化系统输入，文化系统可以输出通用信号，法律系统可以消费这些信号。
`canwu-core`、`canwu-sim` 和 `canwu-api` 不依赖法律语义。扩展之间通过规范化的下一边界输入和有界批次通信，
不使用同步事件总线、可变回调或跨扩展直接写状态。

## 文化系统编写

参考内容包提供可拥有、可序列化的 `CultureDefinition`。Rust builder 与 JSON/TOML loader 应共享同一套校验器，
这样手写内容和生成内容就具有相同的确定性规则。运行开始前，任何超过预算的定义都应被拒绝，而不是把不受控的
扇出留到游戏过程中。

### 定义组件

| 组件 | 作用 | 约束 |
| --- | --- | --- |
| 目标（target） | 表示观念、规范、运动、实践、学派或归属变体 | 有默认中性 profile、谱系、元数据、来源和生命周期策略 |
| cohort | 表示有领地和整数人口的聚合群体 | 分类由应用定义，例如语言、职业、教育或身份 |
| 渠道（channel） | 描述接触或强化机会 | 声明覆盖、信任、解释保真度、延迟、容量和政策修正 |
| 转移（transition） | 把命名信号映射到社会状态 | 使用 awareness、private assent、practice、public alignment、organization tie、mobilization、visibility 等既有维度 |
| 制度与政策 binding | 声明外部决策可改变的压力 | 可影响访问、支持、执行、审查、干扰或迁移压力，但不直接设置 private assent 百分比 |
| 效果 binding | 声明发往下游的信号 | 指定 signal kind、scope、cadence、persistence class 和证据要求，并受批次与扇出预算限制 |

编写层可以使用命名的文化 trait 与 affinity，但运行时必须把它们编译成有界的规则因子或渠道信号。
不能给每个 population bucket 附加一个无限增长的价值 map，也不能通过编写包偷偷创建第二个逐人求解器。

### 编译计划

`CompiledCulturePlan` 只在编译期构建，并且对一个 scenario/run revision 是外部不可变的。它至少包括：

- 目标、cohort、渠道、制度和规则的内部数值 ID；
- 按规范排序的规则表与按目标反向索引；
- 紧凑的渠道、转移、效果和制度表；
- 受影响 cohort 的作用域 key；
- 生命周期索引、编译计划大小、持久化状态大小和每边界预算；
- 绑定精确内容定义的 content hash。

字符串标识只在公开编写边界使用。修改定义或改变编译排序会产生新的 semantic plan revision，不能在现有运行中就地改变计划。
结算只消费已经验证并物化的计划，不读取未经验证的外部文件。

## 增量结算与规模

文化热路径由 active `(cohort, target)` 对的 dirty set 驱动。准入的 exposure、policy change、organization change 或 reactivation
只标记受影响的关系。一次转移边界按以下顺序工作：

1. 按规范顺序消费已准入信号；
2. 只计算 dirty 对及其有界的依赖关系；
3. 增量更新聚合计数；
4. 只刷新能看到变化关系的 observer projection；
5. 为下一个可接收的边界发出有界效果批次。

如果 `D` 是 active 对数量，`Delta` 是 dirty 对数量，`B` 是每对的 bucket 数量，`E_delta` 是受影响的边，
`V_delta` 是受影响的 observer 条目，稳态目标成本约为 `O(Delta * B + E_delta + V_delta)`。
只有定义变更、迁移或明确的维护检查点才需要完整重建计划。当前社会运行时的全状态路径可以作为兼容回退，
但新 API 不应让全扫描看起来没有成本。

## 文化生命周期

每个文化目标都有明确的 generation，并处于 `Active`、`Dormant` 或 `Retired` 之一：

```text
Active -> Dormant -> Retired
             ^          |
             +----------+
        显式重新激活会创建新一代
```

### Active 与 Dormant

`Active` 目标有参与人口、传播活动、制度/政策输入或已安排的重新激活路径，因此其分布、规则和投影可参与普通结算。

在配置的 quiet window 内没有 engaged population 且没有准入工作后，目标进入 `Dormant`。engaged headcount 不是分布总量：
只有中性 bucket 的关系不会让目标保持活跃。休眠目标离开文化 hot/dirty index；上层应用显式同步 society 生命周期后，
其由文化计划编译的转移规则也停止运行。已有的 society 分布和紧凑的 reactivation descriptor 保留，休眠可逆且不表示历史被抹除。

### Retired 与资格判断

目标必须在 retention policy 规定的时间内保持休眠，并且在本边界应用所有已准入信号之后，满足以下条件才可退休：

- 没有活跃转移规则、组织、制度、政策或效果批次引用当前 generation；
- 没有指向当前 generation 的跨扩展输入；
- 没有需要动态状态的待处理 scheduled continuation；
- 没有活的权威依赖要求保留热状态。

退休写入紧凑的 `RetiredTargetTombstone`，其中包括目标身份和 generation、最后活动的模拟时间与 revision、退休原因与 policy hash、
显式 successor/reference（如有）以及重放和审计所需的精确证据引用。退休只释放目标范围内可重建的动态 society 状态；
历史领域记录版本、事件、角色知识和归档证据仍可通过普通契约查询。

### 原子生命周期同步

上层应用应优先使用 `settle_culture_society_boundary`：它先准备有界 runtime delta，只有出现生命周期变化时才暂存 society 变化。
如果存在活的外部依赖，退休会在任一调用方状态改变前失败。上层应用必须在同一个权威事务中保存 culture record、society state 和类型化生命周期转移。
完整扫描的 `synchronize_society_lifecycle` 只适用于加载修复和显式维护检查点。

退休清理不会删除其他扩展的 live organization、policy、influence edge、rule 或 binding。已经退休 generation 的新 exposure 会被稳定地拒绝，
除非先准入显式的 reactivation command 或 ingress。重新激活只初始化必要的 active 关系，引用旧 tombstone 并创建新 generation；
它不会改写旧历史，也不会悄悄复活所有旧 cohort。

## 从文化信号到法律制度

信息和通信扩展先解决访问和解释，再可以发出有界的 `CultureExposureSignalBatch`。文化结算更新 awareness、private assent、practice、
public alignment、organization tie 和 mobilization 等状态，并产生有界的 `CulturalSignalBatch`。批次包含 target generation、scope、strength、
persistence class、cadence 和 evidence；它是法律输入，不是权限授予。

法律桥接只处理 dirty 或到期的辖区和提案：

1. 根据 signal kind 与 scope 的反向索引找到受影响的辖区和开放提案，不扫描无关法律；
2. 类型化 `LegalMutation` 与 holder-context ingress 进入事件驱动的法律插件；插件校验内嵌编译计划绑定、精确 directory/shard 版本、host-owned `expected_versions`、引用的文化 generation、信号提供者精确的 `(plugin, packet_type)`，以及内核提交的生产 boundary；host 直接注入同一 provider namespace 不构成证据，调用方自报的 signal kind 也不具权威性；公开事件还必须匹配保留的 provider payload（proposal、时间、媒介和辖区），一般习俗信号则采用身份与生产 boundary 证据；
3. 程序创建绑定 holder 的决策 outbox。适配器先持久化预期 revision，每个精确席位 controller 最多注册一次，后续 ticket 复用它；只有所需结果都是 `Accepted` 且当前 controller/ticket 与持久化草案精确一致时，ACK 才会通过，ingress 归档不会破坏该证明；
4. 授权控制者从既有选项中选择；被接受的命令只能安排有界的 pending legal intent，不能直接写法律；
5. 后续法律插件边界重新校验权限、程序、revision/effective-time guard、条款/证据上限和文化 generation，然后原子提交 owner-scoped 法律分片 mutation bundle；下游适配器在各自声明的边界消费结果。

如果席位 controller 尚不存在，`canwu-law` 会创建默认 Human controller。上层
应用也可以提前使用相同的稳定 controller ID 注册 Utility、Rule、Random、External
或 LLM 策略；只要 authority、seat、permission profile 和 command subject 与编译计划
完全一致，法律适配器会保留该策略而不是覆盖它。Random 通过操作定址边界抽样
生成决策准入，External/LLM 通过严格的选项选择 DTO 返回已有 option ID；两者都
不能改变法律选项或权限。

权威路径是：

```text
CulturalSignalBatch
  -> LegalProposal / DecisionTicket
  -> 授权的 DecisionAttempt / DecisionTrace
  -> 已接受的法律命令 -> pending intent
  -> 法律分片 bundle 原子提交
  -> LawVersion
  -> 下游执行与反馈证据
```

禁止同步跨扩展回调。下游消费者无法接受某批次时，应记录 rejection 或 defer，而不是部分修改文化或法律状态。

## 法律记录与制度程序

`LegalJurisdiction` 把稳定辖区 ID 绑定到父辖区、领地范围、主管机构和 procedure profile。
`LegalInstitution` 把机构实体绑定到辖区、权限席位、quorum、投票/任命规则和可采纳法律的 command subject。
它们是类型化法律分片状态的成员，不是新的 core entity kind，也不是可由 host 独立修改的记录。

编译期要求每个程序席位只能解析到一个同时声明该程序与席位的机构，并把 holder、permission profile 与采用长度前缀的无碰撞 controller ID 冻结进计划。缺失或歧义的权限定义会在运行开始前失败。

`LegalProposal` 是尚未制定的、带版本的程序输入。它至少记录：

- 提案身份、辖区、发起人和 subject 引用；
- 有界的类型化条款或资格规则；
- 所需程序、截止时间和状态：`draft`、`submitted`、`deliberating`、`adopted`、`rejected`、`expired` 或 `withdrawn`；
- `CulturalSignalBatch` 与其他证据引用；
- 开放中的 `DecisionTicket` 身份和 option version；
- 主张的法律权限、瑕疵、效力状态，以及精确的裁决、协议或承继来源。

内核授权只证明谁提交了命令，不能让一个越权行为自动取得世界内法律效力。提案可以引用某个 cultural target generation，
但这只是证据，不能赋予文化扩展修改或制定法律的权限。

机构权限采用默认拒绝：必须同时覆盖法律秩序、辖区、事项、渊源模式、操作、程序、法院和裁判权。每个渊源 profile 还显式声明程序机构或证据主张这两种 authority policy、允许的来源类型、公开政策与编译后的公开信号提供方、证据上下限、claimant 要求与追溯许可。公开事件只能在对应 provider ingress 实际发生的边界记录；未来公开计划不能冒充已发生事件。`Promulgated` 必须经过程序；`Agreed` 还会编译精确的文书 namespace/kind、至少两方当事人和批准证据。

一个被接受的提案产生一条不可变 `LegalSourceVersion`、稳定 `LegalRule` 和一条不可变 `LawVersion`。
法律渊源保存精确提案和裁决、协议或承继来源，其模式显式区分 `Promulgated`、`Adjudicated`、`Accreted`、`Agreed` 与 `Received`。
规则把“最新主张”与“当前有效版本”分开，因此 `Purported` 或 `Contested` 的变更可见时，先前有效版本仍可继续支配。
公开不是采纳时自动写入的字符串，而是绑定精确 proposal、时间、媒介、范围和证据的不可变 `LegalPublicityEvent`。`ValidityCondition` 缺少公开时会让采纳边界原子失败；`EffectivenessCondition` 则允许先采纳，但新版本在公开前保持惰性，也不会出现在早于公开时间的历史 read cut 中，而且公开不得晚于生效时间。延迟公开只追加事件并更新 proposal 生命周期与派生规则头，不会改写 create-only 的 source 或 law version。追溯效力还必须同时具备 profile 许可和显式追溯日期。

`LawVersion` 记录稳定规则 ID、单调 legal ordinal、辖区和有界 scope、生效时间、渊源与来源、因果证据和前置版本。
每个编译条款显式声明规范模态，不从显示文本猜测。权利和资格规则包含 holder、duty bearer、subject matter、condition、standing、forum 与 remedy profile。
修订和废止都是新的法律命令与新的追加版本；文化目标退休不会删除已经制定的法律。

适用性查询必须指定精确法律秩序与编译 profile，并在预算内完成时间、领地、主体、事项和辖区过滤、优先级决议与 trace 输出。条件和例外是编译 predicate：缺少事实返回 `Indeterminate`，条件为假或例外为真返回 `NotApplicable`。每个事实携带精确 evidence ref；actor-relative 查询还必须绑定 `KnowledgeReadCut` 和 holder knowledge-record ID。host-bound API 会校验 holder、完整 read cut、编译 knowledge schema、JSON 布尔指针、断言值和证据；detached API 拒绝 actor-relative 查询。
未决效力返回 `Contested`，同时暴露先前有效版本与竞争主张。承继不会默认继受整个前法秩序：reception 先按 succession 的属人、属地 scope 与规则前缀选择最长匹配，再应用被接收规则自身的事项 scope；
`Continue` 可直接延续前法，`Transform` 与 `Review` 则需要显式 `Receive` 来源并绑定精确 succession 与 predecessor；`Transform` 还必须绑定并实际使用一个编译条款。

辖区查询使用按 relation kind/direction 编译的邻接表，每次查询只构造一个有预算的可达集合；总查询预算同时限制图边、规则、历史版本、effect/holder/predicate 访问、冲突索引扇出和冲突成员。每条 proposal、case、ruling 和 conflict 还必须在遍历前通过嵌套条目总预算。已解决冲突保存完整、支配与被排除的精确版本集合，以及类型化依据、辖区、记录时间、生效期间和理由；只有完整主张集合与时空范围匹配时才应用分区，分区既可提升争议主张，也可排除它。所有活跃分区同时合并；若同一版本同时被支配与排除，结果保持 `Contested`，不按冲突 ID 决胜。非时间性解决必须引用版本集合完全一致、绑定案件、处于有效状态且覆盖明确辖区的有权裁决。案件、finding 与 ruling 同样受编译 forum、proof、standing、remedy、precedent、期间、issue 和裁判权限约束。

### 效果持久性语义

| 文化效果 | 法律解释 |
| --- | --- |
| `Pulse` | 打开或更新一次提案机会；此时还没有持久法律。 |
| `Level` | 提供当前支持度或合法性压力；结束时可触发法律复核，但绝不自动废止。 |
| `Commitment` | 被法律命令接受后，成为持久 `LawVersion` 的来源；文化退休不能撤回它。 |
| `Evidence` | 仅作为历史引用，不能直接打开或改变法律程序。 |

如果法律规则刻意依赖一个 live cultural level，法律扩展必须记录该依赖并拥有自己的复核、到期或续期规则。
文化运行时只发出 level 结束信号，不会静默废止法律。已被法律接受的 commitment 不会让文化目标继续留在 hot path，因此文化可以退休而法律仍然生效。生效法律只保留一份经过 Merkle 绑定的紧凑采纳证据 receipt；退休文化的传播状态、索引和旧 payload 不再进入热路径，废止或到期仍然必须经过显式法律操作。

退休属于显式、有界的维护操作。Format 8 由内核协调目标 schema 所有者与每个已登记的依赖解析插件；各参与者只能修改自己拥有的记录，完整提案集合针对同一领域根预检并原子提交。法律扩展使用按文化目标分片的依赖记录，因此退休无需扫描全部法律历史；缺少目标所有者提案、跨所有者写入、陈旧版本或超预算都会在根交换前失败。

## 权限、可见性与重放

法律命令沿用参伍的普通权限链：

```text
法律事实 -> DecisionTicket -> 控制者选择
  -> DecisionAttempt / DecisionTrace
  -> 规范化命令输入
  -> 法律权限与程序校验
  -> LawVersion 提交
```

命令 subject 必须是提案冻结的精确主体；机构是否具有世界内法律权限由独立 competence contract 判断。context 携带已校验的 `decision_controller_id`、decision origin、seat、permission profile、request identity 以及预期 revision/time guard。
外部服务或模型可以推荐选项，但不能伪造权限，也不能提交绕过票据的原始法律 payload。

已公开的法律可以通过领域投影提供。私人草案、异议和角色特定知识使用 `ViewerContext` 与 holder ledger，不能用真值回退。
文化和法律记录实现 `DomainRecordType`，采用严格 schema、类型化引用、显式 mutation policy，并在证据需要时保留精确的历史版本正文。

Format 8 将法律状态持久化为独立版本的 plan、directory、order/jurisdiction shard、coordinator、culture-dependency 与 archive-head 记录；加载时只装载声明的工作集，并在暴露状态前重建和校验派生索引、认证归档根与热投影。
精确重放消费已记录的 mutation、信号、决策、命令、ACK、wake ingress 与边界证据，不重新运行人类、服务或模型策略。派生分支复制已验证状态后接受新的因果输入。
失败边界必须原子恢复索引、tombstone、计数器、证据和随机位置。

完整历史与派生索引校验只在冷加载/恢复时运行；实时边界校验不可变 plan/budget 绑定和局部 mutation guard，不再为每条 mutation 重扫全部法律历史。
仍然存活的最新争议主张会保留其身份证据，直到后续主张取代它。

## 有界工作与验收门槛

法律计划应编译辖区、机构、提案、条款和程序 profile 的数值 ID，维护按 signal kind/scope 的反向索引、dirty proposal/jurisdiction set，
并为条款、证据、选项、扇出和待处理 continuation 声明上限，同时将 plan hash 与预算清单绑定到运行。
对于 `P_delta` 个 dirty proposal、`C_delta` 个受影响条款和 `V_delta` 个 observer 条目，目标稳态成本约为 `O(P_delta + C_delta + V_delta)`。
截止时间与未来生效工作使用有序索引，精确决策结果使用 request 索引，适用性删除和插入都计入 mutation 预算；退休目标和历史法律目录不能改变活跃提案的结算成本。

这个复杂度描述分片内语义工作。Format 8 使用持久化 HAMT/Patricia 结构、内容寻址页面 delta、认证法律归档索引和根式冷存储。2026-08-30 的发布探针中，100k 与 1M 冷法律记录下各 50 次普通脏分片边界的中位数/p95 分别为 6.558/11.302ms 与 6.920/11.733ms；冷历史没有进入普通边界增长曲线。100 万记录的真实认证归档索引使用 65,536 个 membership 页、65,536 个 effective-time 页和 65,535 个 recorded-time 页；最大页为 37 条/37,335 字节。100 个抽样稀疏单点查询中，每个查询最多返回一个交集候选。完整构建经过 245 个生产归档批次，热候选始终不超过 4,096 条。边界提案校验把小型 overlay 叠加到结构共享根上，只校验受影响引用闭包；空阶段不会物化未触及记录。独立的 100 万候选 selector 压力探针只检查并物化批次内的 4,096 条，但其候选分片为 2.49 GB，刻意超出实时法律状态与内存各 128 MiB 的契约，因此不是可接纳存档。真实 Canwu 探针使用可接纳的 16,384 候选、38.40 MiB 持久化分片：空边界为 0.169ms，无关法律边界为 2.563ms，候选记录版本保持不变。

归档只改变历史载荷的位置，不会撤销当前法律；文化退休同样不会自动废止已经制定的人权或投票资格规则。时间索引中的密集同时间单元会拆成有序认证分段，单页仍受 64 条与 1 MiB 上限约束。统一 GC 可达性清单在重启后仍标记法律内容/blob/索引页和决策 locator/blob；待处理的已验证维护 ingress 也会精确保留相关对象，应用后转交给已提交根，陈旧拒绝后释放。缺失 provider 会返回明确不可用错误，而不是把未知历史误报为不存在。

每个规范归档结果都会按 retention handle 保留，直到上层应用完成 store 侧交接。finalization 从重新加载的权威法律 runtime 推导已记录结果，并排入私有确认 ingress 来退休该恢复记录。同步 helper 会先认证与 store 绑定的完整 archive head，再在克隆上应用；错误根或失败的 store 转换不会提前释放热载荷。分页决策恢复也遵守相同的有界原则：校验前只加载仍被热决策对象引用的精确归档 ticket/trace locator 页面。

测试和基准证明：

- 文化信号不能直接修改法律记录；
- 只有绑定控制者的授权命令能制定、修订或废止法律；
- 过期 proposal、ticket 和 law revision 会成为安全且可持久化的拒绝；
- 已接受的 commitment 在文化退休后仍然存在；
- 未解决的 live level dependency 会阻止文化退休；
- 未来生效的 live-level dependency 也会阻止提前退休；
- 过期程序会同时过期未解决的 pending/enqueued outbox；
- proposal、law、evidence、archive、snapshot、fork 和 exact replay 保持一致；
- 无关目标、observer 和退休目录条目不会扰动有 key 的结果或已声明预算。

一个典型的女性参政权内容包可以发出 public alignment、organization capacity 和 legitimacy pressure 信号；主管议会通过 `DecisionTicket` 选择投票资格规则，
已接受的命令安排一项法律 intent，由后续法律边界以确定性生效时间提交 `VotingEligibilityRule`，选举适配器再读取该法律。这里的“成年女性”必须由具体内容包按历史语境定义：公民资格、种族、财产、婚姻、殖民地身份和登记制度都可能形成交叉排除。文化目标后来退休时，只停止新的传播，已制定法律和执行历史仍然保留。

启蒙与人权内容包也不应写成一条从欧洲观念自动通往现代权利的直线。它可以把多元思想来源、翻译、印刷、教育与结社网络建模为不同传播通道，同时加入宗教、王朝、地方共同体和既得利益的反动员；这些信号只能改变公共 alignment、组织能力、合法性压力和决策证据。不同法律秩序仍可部分采纳、重新解释、延迟公布、选择性执行或拒绝相关主张。
