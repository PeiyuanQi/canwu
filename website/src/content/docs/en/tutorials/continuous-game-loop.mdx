This reference implementation targets continuously running strategy games with pause and speed controls. The host owns wall time, game speed, the sub-minute accumulator, and presentation state; Canwu receives only representable deterministic simulation time.

## Run it

```shell
cargo run -p canwu-api --example continuous_game_loop
```

## Three clocks

- **Wall clock:** frame durations from the renderer or game framework. The example uses predefined sequences that approximate 60 FPS and 30 FPS, never the real clock or `sleep()`.
- **Simulation clock:** Canwu's authoritative integer-minute time. The host calls `advance_canonical()` only after at least one minute has accumulated.
- **Presentation clock:** Canwu time plus the host's retained sub-minute remainder, used only for visual interpolation.

<Steps>
1. Scale each frame duration by the host's base calendar rate and `Paused`, `1x`, `5x`, or `20x` game speed.
2. Accumulate the result as high-precision integer nanoseconds, retaining any fraction smaller than one `SimDuration` minute.
3. For every completed simulation quantum, call `advance_canonical(SimDuration::minutes(1))`.
4. Copy transit data from the public `WorldSnapshot` into presentation state and calculate read-only movement progress.
</Steps>

## FPS-independent command ordering

The player order enters through `enqueue_command()`. The example defines one frame-independent ceiling policy for between-minute input: a command captured at half a minute is due at the next representable Canwu minute. That timestamp policy belongs to the host and must not depend on which render frame happened to poll input.

At the end, the two render profiles compare Canwu time, world state, commands, events, authoritative state hash, checkpoint hash, and canonical boundary count. Their frame counts differ; their authoritative results are identical.

## Smooth presentation stays outside simulation

The public snapshot exposes transit `from`, `to`, `departed_at`, and `arrives_at`. The presentation layer computes:

```text
visual_progress =
  (presentation_time - departed_at) / (arrives_at - departed_at)
```

This floating-point value never feeds back into Canwu. During pause, render frames continue while simulation time, the retained remainder, and visual progress all remain unchanged.

See [Integrate and drive the simulation](/en/developer/integration/) for the host-side integration rules.
