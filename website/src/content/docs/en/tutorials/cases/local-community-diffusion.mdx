## 1. What problem are we solving?

`canwu-society` is a published **social diffusion simulation module** and,
architecturally, a **domain extension** for Canwu. This example uses an abstract
“new idea” to show how it composes group contact, private assent, public
expression, organizational influence, institutional response, and actor-relative
estimates. It focuses on diffusion mechanics and engine contracts so the same
model can support different historical or fictional settings.

A single “acceptance” score cannot distinguish awareness, private assent,
public expression, participation, and organized mobilization. The model is
also hard to trust if an institutional policy can instantly rewrite what
people privately believe.

This example needs to:

- store population distributions only for groups and targets that actually
  participate in the simulation, rather than allocate a huge dense matrix;
- track awareness, private assent, practice, public alignment, organization
  ties, mobilization, and visibility separately;
- treat social contact and organization networks as opportunities for
  diffusion, while explicit transition rules determine actual movement;
- let a local institution choose a policy through a `DecisionTicket`, then
  apply its effect at the next society boundary;
- return fallible estimates only to authorized actors instead of exposing the
  authoritative aggregate as player-visible truth;
- persist remainders, policies, projections, and evidence so restoration,
  forks, and exact replay reproduce the same result.

The “new idea” is deliberately abstract. Historical doctrines, rituals,
people, policy labels, cultural compatibility, conflict conditions, and
narrative remain downstream domain concerns. `canwu-society` is a published
optional extension and is not re-exported by `canwu-api`. This
tutorial demonstrates an extension pattern, not a frozen
universal social or religion API.

## 2. How does the example work?

The example composes these systems:

| System | Role in this example | Related documentation |
| --- | --- | --- |
| The `canwu-society` extension | Define cohorts, distributions, influence edges, institutional inputs, and actor projections | [Extend with plugins](/en/developer/extensions/) |
| Settlement | Execute population transfers in stable order and delay institutional effects until the next boundary | [Settlement system](/en/architecture/settlement/) |
| Decisions and authoritative commands | Select an existing policy option and record it through an ordinary plugin command | [Architecture overview](/en/architecture/), [Integrate and drive the simulation](/en/developer/integration/) |
| Actor-relative reads | Materialize estimates for observers without a ground-truth fallback | [Read and present state safely](/en/developer/reading-state/) |
| Persistence and exact replay | Retain transfer remainders, plugin state, projections, and journal evidence | [Save, replay, and fork](/en/developer/persistence/) |

Start by running the example:

```shell
cargo run -p canwu-society --example local_community_diffusion
```

The program creates market and village cohorts. A small group in the market
already supports the target, while market contact and a local organization
create opportunities for diffusion into the village. Day one produces
awareness and a little private assent. A local institution then selects a
public policy through a `DecisionTicket`; the society boundary applies that
institutional input on day two.

### Implementation path

```text
cohort + affiliation target
  -> sparse disposition distribution
  -> influence / organization / institution signals
  -> deterministic integer transitions + persisted remainder
  -> aggregate truth
  -> authorized observer estimate
```

<Steps>
1. Create two integer-headcount cohorts and store distributions only for active `(cohort, target)` pairs.
2. Keep awareness, private assent, practice, public alignment, organization ties, mobilization, and visibility distinct.
3. Calculate diffusion pressure from bounded influence edges and organization topology.
4. Let a named controller select an existing policy option and record it through an ordinary plugin command.
5. Apply the institutional input at the next daily boundary, then settle integer transfers in stable rule-ID and cohort-ID order.
6. Materialize a fallible estimate for an authorized observer; an actor without a projection receives an error, never a ground-truth fallback.
7. Save, restore, fork, and exactly replay the same result from the journal.
</Steps>

### Step one: represent population state with sparse distributions

Each active `(cohort, target)` pair stores several `DispositionBucket` values.
A profile keeps the dimensions separate:

```rust
DispositionProfile {
    awareness,
    assent,
    practice,
    public_alignment,
    organizational_tie,
    mobilization,
    visibility,
}
```

The bucket `headcount` values must sum exactly to the cohort population.
Different targets have independent distributions, so the extension does not
assume that every social identity is mutually exclusive. An absent pair also
does not consume a dense
`territory * cohort * target * channel` allocation.

### Step two: separate opportunities for diffusion from actual conversion

A `SocialInfluenceEdge` supplies reach and trust only. Its source may be a
cohort, organization, or institutional alignment. Downstream
`TransitionRule` configuration decides how those signals move people from one
profile to another.

Transfers use integer headcounts. An expected amount below one person remains
in a stable `TransitionRemainder` and accumulates at later boundaries. This
avoids silently losing population and gives snapshot restoration and replay the
same inputs.

### Step three: apply institutional policy at the next boundary

The example binds a controller to an authorized person and supplies two
existing options. The utility policy can select only an option ID. The selected
option then passes through the `set_institutional_policy` command into a
pending component:

```text
DecisionTicket -> controller-derived authority -> plugin command
    -> pending policy component -> next daily society boundary
```

Immediately after command admission, the example asserts that every population
distribution is unchanged. On day two, institutional enforcement may move
public alignment faster than private assent, but it still cannot assign a
percentage of sincere belief directly.

### Step four: generate actor estimates instead of leaking truth

`projection_for_viewer()` requires a Canwu-issued `ViewerContext` and returns
only the `SocietyProjection` created for that actor during the
`PerspectiveAndReportMaterialization` settlement phase. Detection, concealment,
and false positives make the estimate differ from the true aggregate. An actor
without an observer profile receives an error instead of the society root record.

The example restores through `from_society_snapshot_json()`. After Canwu's
generic snapshot checks, this module boundary rechecks the core references
named by the society payload and every materialized derived value. The example
then verifies that a fork and journal replay rebuild the same authoritative
state.

### Step five: emit mobilization candidates and leave conflict to the domain

`MobilizationBand::Active` may produce a `MobilizationCandidate` containing
population, organization capacity, and policy-pressure evidence. It is not a
conflict event. Separate political and security extensions must decide whether
the result qualifies as protest, repression, migration, riot, coalition, or
war.

## Domain-extension boundary

Reusable mechanics in this domain extension are cohorts, sparse multidimensional
distributions, deterministic transfers, influence edges, organization
topology, institutional inputs, policy pressures, candidate outputs, and actor
estimates. Historical doctrine, ritual, people, cultural compatibility, policy
labels, conflict qualification, and narration remain downstream domain data.

`canwu-society` is published but is not re-exported by `canwu-api`. It is an
optional domain extension that uses the public
plugin contracts. Its current documented scope covers generic diffusion
mechanics; historical content and domain-specific APIs remain downstream.

For larger culture systems, the published `canwu-culture` SDK compiles these
definitions into a bounded execution plan and exposes restorable dirty-relationship
and hot-target indexes. Society aggregation still uses the full-state path;
incremental refresh remains follow-up work. A target with no engaged population
can become `Dormant` and leave the culture hot index; host-driven society sync
then stops its compiled culture transition rules. If it later becomes `Retired`, synchronization
releases target-scoped dynamic state while a tombstone preserves its history.
Explicit reactivation creates a new generation. See the [culture and legal institutional systems](/en/architecture/culture-law/)
and the [complete benchmark contract](https://github.com/PeiyuanQi/canwu/blob/main/docs/proposals/culture-authoring-sdk-and-lifecycle.md).
