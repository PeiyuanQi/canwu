This audit asks which layer owns a meaning, not which crate has too few lines. The result is: **do not broadly consolidate crates**. Concrete event payloads have moved out of generic `EventKind`; the next step is still to move period- and application-specific world entities into reference integrations before removing package boundaries that genuinely have no independent responsibility.

<Aside type="note" title="Migration status">
`EventKind` is now a generic type-tag and structured-fields record; legacy event JSON and the snapshot format are unchanged. Published `canwu-world` versions are yanked, but the source crate, existing consumers, and dependency DAG remain until the reference-world migration completes.
</Aside>

## One ownership rule

Generic engine crates own deterministic simulation contracts. Reference integrations own concrete world entities such as armies, governments, territories, people, and letters, plus the event payloads that describe their domain behavior.

That rule gives the two candidate crates different outcomes:

| Crate | Audit result |
| --- | --- |
| `canwu-world` | It remains the compatibility world model for the first movement vertical slice. Published versions no longer admit new resolution; the source crate can retire only after its model and compatibility path move to a reference integration. |
| `canwu-event` | It now contains only generic event contracts and a structured event record. Concrete payloads are extracted; decide whether the residual generic types belong in `canwu-sim` only after their independent consumption is known. |

## The 12 public `canwu-world` types

| Public type | Classification | Target owner |
| --- | --- | --- |
| `MapPoint` | Concrete map and presentation model | Reference world integration |
| `Person` | Concrete person model | Reference movement/world integration |
| `PersonTransitState` | Concrete person journey state | Move with `Person` |
| `LetterStatus` | Concrete letter custody and delivery lifecycle | Reference information/logistics integration |
| `LetterCargo` | Concrete letter body, parties, location, and custody | Reference information/logistics integration |
| `Government` | Concrete government and capital model | Reference political/world integration |
| `Territory` | Concrete territory, controller, and coordinate model | Reference topology/world integration |
| `Route` | Concrete bidirectional territory route | Reference topology integration, adapted to routing's own `PlanningSnapshot` |
| `TransitState` | Concrete army journey state | Reference movement/world integration |
| `Army` | Concrete unit, commander, strength, and morale model | Reference movement/world integration |
| `WorldSnapshot` | Compatibility projection containing only the concrete entities above | Keep a migration adapter, then let each integration own its detached projection |
| `WorldDiff` | Compatibility diff limited to army, person, territory, and letter IDs | Keep until callers migrate, then use integration diffs or generic change evidence |

`canwu-routing` does not need to own this world. Its solver already consumes the generic `PlanningSnapshot`; the current `WorldSnapshot` dependency is only a conversion function. That conversion should move with the reference integration.

## The 4 public `canwu-event` types

| Public type | Classification | Target owner |
| --- | --- | --- |
| `CauseRef` | Generic engine contract | Preserve command, parent-event, boundary, and system causes plus serialized compatibility |
| `EventAudience` | Generic engine contract | Preserve private-by-default, actor-scoped, replay-stable visibility |
| `SimEvent` | Generic event envelope | Preserve identity, time, affected references, summary, cause, and correlation ID |
| `EventKind` | Generic type tag and flattened structured-field record | Preserve the legacy JSON wire shape; domain owners define typed payloads outside this crate and use the generic encode/decode API |

Typed payloads for movement, army arrival, person travel, letter delivery, report dispatch, knowledge, and debug fields are no longer public `canwu-event` variants. Private compatibility payloads in the reference runtime still validate the legacy tags and fields strictly; they move again with their world, knowledge, or debug integration. Plugin events expose their compatibility namespace through `plugin_identity`.

## Why direct merges fail

- Folding `canwu-world` into `canwu-core` would make one historical worldview foundational.
- Folding `canwu-event` into `canwu-sim` now would still enlarge the persistence blast radius; independent use of the remaining generic contracts must decide that boundary.
- Creating `canwu-model` would consolidate names without clarifying responsibilities.
- Merging `canwu-api` and `canwu-sim` would erase the public-facade/private-runtime boundary.

## Safe migration sequence

<Steps>
1. Representative JSON saves, event journals, `canwu-api` calls, and exact replay outcomes are frozen.
2. `EventKind` is now a generic structured record and its concrete public variants are extracted without changing legacy JSON. A complete cross-integration namespace and payload-version contract remains future work.
3. Build a first-party reference world integration through public APIs and move the concrete entities, event payloads, and routing conversion into it.
4. Migrate the facade, saved state, and starter kits under the versioning policy without silent source or wire breaks.
5. Retire `canwu-world` after it has no normal consumers; after private compatibility event payloads move to their owners, decide whether `canwu-event` should fold into `canwu-sim`.
</Steps>

## Completion gates

Old supported saves and journals must load through explicit version migrations and reproduce exact replay outcomes. Cause, correlation ID, audience, affected-reference, and commitment validation must stay deterministic and fail closed. Routing must no longer depend on the example world. At least one runnable starter kit must prove save/load, fork, and exact replay, and a second integration or fixture must prove the generic engine does not depend on the first historical model.

The canonical repository audit records the complete per-type rationale, dependency evidence, and gates.
