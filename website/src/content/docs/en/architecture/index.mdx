Canwu is a headless historical simulation engine. A client may be a game, research tool, debug UI, or agent, but every client reaches the simulation through the same public boundaries instead of receiving a mutable reference to the live world.

## Workspace crates

| Crate | Core responsibility |
| --- | --- |
| `canwu-core` | Typed IDs, deterministic random utilities, and schema metadata |
| `canwu-time` | Historical timestamps and checked duration arithmetic |
| `canwu-decision` | Decision tickets, deterministic evaluation, controllers, and policy SDK |
| `canwu-event` | Generic event envelopes, provenance, audiences, and structured event records |
| `canwu-reference-world` | Replaceable example entities, movement plugin, detached projection, routing adapter, and starter |
| `canwu-knowledge` | Actor knowledge, source, confidence, and information age |
| `canwu-routing` | Deterministic time-dependent routing primitives |
| `canwu-transport` | Transport execution, itinerary revision, handoff, booking, and saga primitives |
| `canwu-sim` | Private runtime, scheduling, plugins, and settlement |
| `canwu-api` | Generic programmatic API, canonical commands, domain records, evidence, and replay |
| `canwu-information` | Published authoritative information lifecycle extension |
| `canwu-correspondence` | Published correspondence domain extension and simulation plugin |
| `canwu-society` | Published social diffusion simulation module |
| `canwu-culture` | Published culture authoring, compilation, and lifecycle extension |
| `canwu-law` | Implemented experimental legal authoring, institutional procedure, versioned law, and applicability extension |
| `canwu-technology` | Published evidence-based generic technology simulation extension |
| `canwu-history-research` | Optional downstream historical research assessment plugins |
| `canwu-fiscal` | Generic fiscal procedure, regional adoption, assessment, execution receipt, and holder-relative knowledge-report extension |
| `canwu-resource` | Conserved resource accounts, protected floors, demand, reservation, allocation, transfer, consumption, loss, and fulfillment extension |
| `canwu-production` | Processes, production sites, facilities, capacity, work orders, work in progress, production execution, projects, and output settlement extension |
| `canwu-ming-fiscal` | Source-cited reference content from the early Ming through the Southern Ming with complete coverage declarations |
| `canwu-economy-reference-content` | Economy reference content with model cards, citations, coverage declarations, and explicit unknown/not-applicable states |
| `canwu-ming-fiscal-reference` | Runnable Hongwu, Wanli, and Hongguang fiscal reference integration |
| `canwu-force-supply-reference` | Replaceable military-supply consumer and requisition-saga reference integration using the public resource API |
| `canwu-economy-reference` | Runnable integration composing resources, production, transport, force supply, a grain loop, scarcity, and price evidence |
| `canwu-debug` | Reference client using the public API and reference-world integration |

The published `canwu-culture` culture system SDK sits above
`canwu-society`, not in the simulation core. It compiles versioned content into
an externally immutable, content-hash-bound execution plan, enforces cardinality and
expanded fan-out budgets, and provides dirty-set and hot-target indexes. Its
complete state restores lifecycle schedules, hot/dirty indexes, and effect
cadence. Dormant targets leave the culture hot index and stop compiled culture transition rules
after explicit society synchronization; retired targets additionally release
target-scoped dynamic society state while historical evidence remains available.
Boundary-system registration, canonical signal admission, and incremental
aggregation remain follow-up work. See the standalone [culture and legal institutional systems](/en/architecture/culture-law/),
which combines culture authoring, lifecycle, and legal institutionalization design.

## From domain extensions to runnable kits

Canwu provides more than kernel contracts. Generic domain extensions provide
reusable mechanics, reference content packs provide replaceable domain data,
reference integrations connect those capabilities to a small world, and
starter kits compose them into vertical slices developers can run and extend.
All of these layers remain above the kernel; no historical world is embedded in
`canwu-core`.

`canwu-correspondence` is a domain extension by ownership: it owns
communication demand, address resolution, accepted routes, disaster and
interception policy, and cross-mechanism evidence. It is also a
`SimulationPlugin` by execution form, registering authoritative commands,
canonical ingress, and boundary systems. It depends on `canwu-api` and
`canwu-information`, with no reverse dependency, so the crate DAG stays acyclic.

Resources and production follow the same ownership boundary:
`canwu-resource` owns conserved quantities and fulfillment only;
`canwu-production` consumes resource outcomes and exact technology evidence
while owning production assets and work-order lifecycles;
`canwu-force-supply-reference` is a second independent resource consumer; and
`canwu-economy-reference` composes them with routing, transport, and a seasonal
grain loop. Scarcity and price pressure remain detached, holder-bound read
projections. Without executed, quoted, administered, or contracted price
evidence, the integration does not invent a price.

Reference content packs are data, not new solvers. Reference integrations must
use the public API and be replaceable by another world or economy model. Starter
kits must demonstrate scenario creation, commands, settlement, actor-relative
reads, save/load, forks, and exact replay. The collection is expected to grow;
it is not a privileged path for one fixed demo.
