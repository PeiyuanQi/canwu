Use this page to look up a Canwu term: its English and Chinese names, the
matching code identifier, and what it means. Linked terms have their own page
with more detail; the others are defined here and in the API documentation.

If you write Canwu documentation, use the listed term for each language, keep
code identifiers unchanged, and avoid the alternatives marked as deprecated in
the last table. In Chinese prose, you may add the English term or code name in
parentheses at first use, for example 模拟插件 (`simulation plugin`). The source
of truth is
[`docs/terminology.md`](https://github.com/PeiyuanQi/canwu/blob/main/docs/terminology.md);
this page mirrors it.

## Product and runtime boundaries

| English | 中文规范写法 | Code or API | Meaning and use |
| --- | --- | --- | --- |
| [Canwu](/en/architecture/) | 参伍 | `Canwu` | Product name and main public API entry point. Do not translate the brand as a generic noun. |
| [headless historical simulation engine](/en/architecture/) | 无界面历史模拟引擎 | — | Canwu's product category: it simulates historical worlds without owning rendering, audio, or production UI. |
| [simulation core](/en/architecture/) | 模拟内核 | `canwu-sim` | The private runtime that owns mutable authoritative state, scheduling, settlement, persistence, and replay. |
| [host application](/en/developer/integration/) | 上层应用 | — | A game, research tool, service, client, or agent system that embeds Canwu. Chinese prose uses 上层应用, not 主机程序. |
| [public API](/en/developer/integration/) | 对外 API | `canwu-api` | The supported API boundary for application code. |
| [simulation run](/en/developer/persistence/) | 模拟运行 | `run_id` | One causally continuous execution with its own identity, inputs, state, and evidence. |
| [scenario](/en/tutorials/move-army/) | 场景 | `Scenario` | The initial world and configuration used to create a simulation. |
| [authoritative state](/en/developer/reading-state/) | 权威状态 | `SimulationSnapshot` | State owned and validated by Canwu and used as the basis for commitments, persistence, and replay. |
| [ground truth](/en/developer/reading-state/) | 真值 | — | Facts present in authoritative state whether or not a particular actor knows them. |
| [actor-relative view](/en/developer/reading-state/) | 角色相对视图 | `CanwuViewer`, `ViewerContext` | A read surface derived from one actor's knowledge and authority rather than omniscient state. |
| [read-only snapshot](/en/developer/reading-state/) | 只读快照 | `WorldSnapshot` | A detached state value for trusted reads, not a mutable reference to the live runtime. |

| group | 群体层 | `SimulationGranularity::Group` | A bounded social, institutional, military, or organizational group. A host application may map it to Special Group. |
| actor | 角色层 | `SimulationGranularity::Actor` | A person or other principal with knowledge and authority. A host application may map it to Character. |

## Time, input, and settlement

| English | 中文规范写法 | Code or API | Meaning and use |
| --- | --- | --- | --- |
| [wall time](/en/tutorials/continuous-game-loop/) | 现实时间 | — | Real elapsed time observed by the host application. It never enters authoritative state directly. |
| [simulation time](/en/tutorials/continuous-game-loop/) | 模拟时间 | `SimTime`, `SimDuration` | Deterministic, representable time settled by Canwu. |
| [presentation time](/en/tutorials/continuous-game-loop/) | 表现时间 | — | Client-side animation or interpolation time; it may be fractional and is not authoritative. |
| [command](/en/developer/integration/) | 命令 | `Command`, `CommandEnvelope` | A typed request to change authoritative state through structural, precondition, and authority checks. |
| [domain command](/en/tutorials/move-army/) | 领域命令 | `Command::Plugin` | Typed intent defined by a domain integration and validated through public canonical ingress. |
| [canonical ingress](/en/architecture/events/) | 规范化输入 | `IngressRecord` | The persisted, deterministically ordered input path for commands, communication, information, and scheduled systems. |
| [admission](/en/architecture/events/) | 准入 | — | The decision and cut that determine which pending inputs belong to a boundary. It is not a synonym for ingress. |
| [plugin ingress cancellation](/en/developer/integration/) | 插件输入撤回 | `cancel_plugin_ingress`, `IngressPayload::PluginCancellation` | Terminal withdrawal of one still-queued plugin ingress item strictly before its due time, journaled as its own record. The withdrawn item is never admitted; nothing is rolled back. |
| [cancellation authority](/en/developer/integration/) | 撤回权限 | `IngressCancellationAuthority` | Who withdrew a queued plugin item: the host for public packets it enqueued, the owning plugin's registration permit for its internal packet type, or a boundary system of the plugin that scheduled the item. Only the issuer may withdraw. |
| [pending ingress](/en/developer/persistence/#continuation-checkpoints) | 待处理输入 | `pending_ingress`, `CanwuRun::pending_ingress` | Ingress records queued and not yet admitted or withdrawn, in the order boundaries will admit them, including records a seal or a continuation restore pinned. A trusted host lists them with `pending_ingress`; the list covers every source and is not on `SimulationView` or `CanwuViewer`, so the host selects its own items before showing any to an actor. |
| [scheduled work](/en/architecture/events/) | 调度工作 | — | Work assigned a deterministic simulation due time and insertion order. |
| [boundary](/en/architecture/settlement/) | 结算边界 | `BoundaryRequest`, `BoundaryRecord` | One validated, all-or-nothing settlement pass that admits work, runs systems in fixed phases, records evidence, and commits or rolls back. |
| [settlement phase](/en/architecture/settlement/) | 结算阶段 | `BoundaryPhase` | One position in the fixed boundary execution order, not an independent settlement algorithm. |
| [atomic commit](/en/architecture/settlement/) | 原子提交 | — | Applying all validated boundary changes together so observers never see partial state. |
| [rollback](/en/architecture/settlement/) | 回滚 | — | Restoring state, evidence, counters, and random positions when a boundary fails. |
| [transition manifest](/en/architecture/settlement/) | 转移清单 | `TransitionManifest`, `BoundaryDirective::RegisterTransitionManifest` | A coordinating plugin's declaration of the participant plugins, expected record versions, and single ready boundary of one multi-owner transition. Participants stage their writes with `StageTransitionWrite` in phase 10 of that boundary; phase-10 directives outside a manifest are unaffected. |
| [transition audit](/en/architecture/settlement/) | 转移审计 | `TransitionAuditRecord` | The kernel's phase-11 check of every manifest ready at a boundary. A partially staged manifest or a wrong expected version fails the whole boundary; a manifest no participant staged expires. The committed or expired outcome is read-only boundary evidence for phase-12 systems. |
| [boundary ledger](/en/architecture/settlement/#counting-the-boundaries-of-a-period) | 边界账 | `SimulationView::boundaries_between`, `BoundaryWindow`, `BoundarySummary`, `BoundaryIngressOrigin`, `boundary_schedule_horizon` | The boundaries of a window of simulated time: those settled in it, the one being settled, and those still queued, each with its time, cadences, calendar marks, and ingress counted by class, kind, and origin. Only a phased boundary system may read it, after declaring `canwu.core.boundary_schedule`, to count a period's boundaries before it carries work into another one; it declares how far back it reads with `boundary_schedule_horizon`. Settled boundaries are the same in live, sealed, restored, and replayed runs; the queued list is a lower bound. |
| [calendar mark](/en/architecture/settlement/#counting-the-boundaries-of-a-period) | 历法标记 | `CalendarMark`, `schedule_calendar_marks`, `SimulationView::calendar_marks` | A host calendar's mark on a calendar boundary: the boundary is a period start (of a cadence) of that calendar. A system with a calendar key wakes only on its own calendar's marks of its cadence; a system without one wakes on every boundary of its cadence, marked or not. The core keeps no calendar. |
| [calendar key](/en/architecture/settlement/#counting-the-boundaries-of-a-period) | 历法键 | `BoundarySystemContract::calendar`, `MAX_CALENDAR_KEY_BYTES` | The host's name for one of its calendars (a canonical label of at most 64 bytes), on a mark and on a boundary system's registration, where it is part of the plugin descriptor. |
| [boundary profile](/en/architecture/settlement/#profiling-a-boundary) | 边界耗时明细 | `BoundaryProfile`, `set_boundary_profiling`, `take_boundary_profiles`, `replay_from_journal_with_boundary_profiles` | An opt-in host diagnostic: the wall time of one settled boundary, of each plugin handler it ran, by kind, phase, plugin, and name, and of each engine phase. It is never part of authoritative state, evidence, a snapshot, or replay, and no plugin can read it. An exact replay can be profiled boundary by boundary. |
| [engine phase](/en/architecture/settlement/#profiling-a-boundary) | 引擎阶段 | `BoundaryEnginePhase`, `BoundaryEngineTiming`, `BoundaryProfile::engine` | One kind of the simulation core's own work inside a boundary, timed in a boundary profile: admission, system dispatch, staging, commit, knowledge, journal, and hashing. The engine phases and the plugin handlers partition a boundary's wall time. It is a profiling category, not a settlement phase. |
| [request outcome retention](/en/developer/persistence/#version-and-save-compatibility) | 请求结果保留期 | `RunConfiguration::request_outcome_retention`, `with_request_outcome_retention`, `DEFAULT_REQUEST_OUTCOME_RETENTION`, `MAX_REQUEST_OUTCOME_RETENTION` | How long, in simulated time after its attempt, a tracked command request's exact outcome and queued receipt are kept to answer an exact retry: 30 days by default, from zero to 366, fixed when the run is created. The rule is simulated time alone, so a wall-clock pause retires nothing, a fast simulation speed retires sooner in wall time, and unsealed, sealed, restored, and replayed runs answer alike. |
| [retired request outcome](/en/developer/persistence/#version-and-save-compatibility) | 已退役请求结果 | `ErrorCode::RequestOutcomeRetired`, `RetiredRequestRange`, `RequestIndex::retired_commands` | What a tracked command request becomes once its attempt is older than the retention: its outcome is no longer kept, its ID stays used for the run inside a canonical range of retired IDs, and every later request with that ID, an exact retry or not, is refused with `RequestOutcomeRetired` without an attempt, a revision, or an event. A host that treats `IdempotencyConflict` as "take another ID" treats it the same way. Not 退休目标 (a culture target) and not 已清退条目 (a knowledge entry). |

| [law version](/en/architecture/culture-law/) | 法律版本 | `LawVersion` | A create-only immutable normative change tied to a stable `LegalRule`, with exact source and predecessor refs, normative relations, applicability, effective and validity state, and evidence; enforcement is separate. |
| [legal record reference](/en/architecture/culture-law/) | 法律记录引用 | `LegalRecordRef` | The exact kind and identity of a legal object within the sharded legal runtime. | [caseload profile](/en/architecture/culture-law/#aggregate-caseload) | 案件量配置 | `CaseloadProfileDefinition`, `LegalDefinition::caseload`, `CompiledLawPlan::caseload` | The part of a legal definition that declares what a plan settles in aggregate: the case classes (up to 64), the review levels (up to 16), the periods kept per jurisdiction (1 to 120), and the reports examined per boundary. | [aggregate caseload](/en/architecture/culture-law/#aggregate-caseload) | 汇总案件量 | `AggregateCaseloadRecord`, `LegalCaseloadHead`, `caseload_intake_v1`, `enqueue_caseload_intake`, `load_legal_caseload` | Routine justice counted rather than followed case by case: a host's report of intake and resolutions per case class and of entries and conclusions per review level, for one jurisdiction and one period that starts where the newest settled period ends, settled by the law admission system into one record per kept period (a fixed ring of slots behind a head) with the pending stock carried forward and conserved. A repeat of the newest period is already settled; every refused report changes nothing and is one `canwu.law.caseload_rejected.v1` event with a stable code. The records declare no evidence, never load the legal runtime, and lie outside the legal state budget. A case the host follows on its own is still a `LegalCase`, counted in its class's intake. |
| [clearance rate](/en/architecture/culture-law/#aggregate-caseload) | 结案率 | `AggregateCaseloadRecord::clearance_bp` | Resolutions over intake of one caseload period, in basis points, computed by the engine from the settled counts; absent when nothing arrived in the period. |
| [cultural target generation reference](/en/architecture/culture-law/) | 文化目标代际引用 | `CulturalTargetGenerationRef` | The exact target and generation cited by a legal proposal or version, preventing retirement or reactivation from silently rebinding old evidence. |
| [compiled culture plan](/en/architecture/culture-law/) | 文化执行计划 | `CompiledCulturePlan` | An externally immutable, content-hash-bound runtime plan containing compact IDs, reverse indexes, budgets, and lifecycle policy compiled from a culture definition. |
| [dormant target](/en/architecture/culture-law/) | 休眠目标 | `Dormant` | A culture target with no engaged population or admitted work that has left hot settlement indexes but retains an explicit reactivation descriptor. |
| [retired target](/en/architecture/culture-law/) | 退休目标 | `Retired` | A culture target removed from hot dynamic state while historical identities and evidence remain available through tombstone and archive contracts. |
| [culture boundary plugin](/en/architecture/culture-law/) | 文化结算插件 | `CultureBoundaryPlugin` | The in-engine form of culture settlement: a Monthly phase-7 system consumes admitted exposure batches, persists culture state, and hands society lifecycle deltas to the society plugin, which remains the only society writer. | [exposure signal batch](/en/architecture/culture-law/) | 接触信号批次 | `CultureExposureSignalBatch`, `culture_exposure_v1` | A bounded, evidence-bearing report that cohorts were exposed to one culture target generation, produced by an information or correspondence provider after access and interpretation and admitted at a later boundary. |
| [cohort headcount rebase](/en/tutorials/cases/local-community-diffusion/) | cohort 人口校准 | `CohortHeadcountRebaseV1`, `cohort_headcount_rebase_v1` | Canonical ingress that resets a cohort's headcount to a cited external stock record, which must be current when the packet is admitted, and re-proportions every distribution with deterministic integer remainders at the next society settlement. |
| [society settlement cadence](/en/tutorials/cases/local-community-diffusion/#settle-on-another-cadence) | society 结算节奏 | `SocietyPlugin::with_settlement_cadence`, `SocietyPlugin::DAILY` | The `SystemCadence` category whose boundaries settle society: `Daily` by default, or a category the host chooses. | [transfer settlement](/en/tutorials/cases/local-community-diffusion/#settle-on-another-cadence) | 转移结算模式 | `TransferSettlement`, `SocietyPlugin::with_transfer_settlement` | How a society settlement checks the cohort transfers due at it. **Batch** (批量结算, the default) checks every due transfer against the state at the start of the settlement and applies the ones that still fit in admission order, each to the state the earlier ones left; a transfer whose quantity no longer fits settles as `insufficient_source`. **One by one** (逐笔结算) checks each transfer against the state the earlier transfers of the same settlement left, so of the due transfers that share a cohort one completes and the others settle as `stale_source`. The mode is part of the plugin identity. |
| society ingress queue | 社群输入队列 | `SocietyIngressQueue`, `SocietyIngressBatch`, `society_ingress_queue_entries` | The owner-side queue of rebases, lifecycle deltas, and pressure revisions that wait for the next society settlement: a small head record and one batch record per admitting boundary, so its evidence follows what each boundary admits. | cohort class | cohort 类别 | `CohortClass`, `SocietyState::cohort_classes`, `MAX_COHORT_CLASS_TEXT_BYTES` | The set of cohorts whose classification carries one value, named by the classification's dimension and value as authored (any text of up to 4,096 bytes). | intergroup relation | 群体间关系 | `IntergroupRelationEdge`, `IntergroupRelations`, `intergroup_relation_revision_v1`, `load_intergroup_relations` | A directed, typed relation from one cohort class toward another in an optional region (a territory, a government, or a domain entity), with acceptance, tension, and trust per mille, bounded evidence, and a revision.
