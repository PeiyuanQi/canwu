Canwu keeps the simulation core domain-neutral. Applications add military, economic, political, or social rules through
`SimulationPlugin`, public schemas, command handlers, and boundary systems rather than mutating the live world.

## Choose an extension path

| Need | Use |
| --- | --- |
| A user action or service request produces a local change | Plugin command through `register_command()` |
| Several systems coordinate at the same day, turn, or time point | Boundary system through `register_boundary_system()` |
| The plugin owns typed domain data | Domain schemas and record APIs |
| Results require stable randomness | Declared plugin random streams so draws enter evidence |

## Command plugins

A command plugin should:

1. Provide a stable name, version, and semantic hash.
2. Declare its payload schema and read/write `StateKey` values with `PluginActionDescriptor`.
3. Query through read-only `SimulationView` and check authority from `CommandContext`.
4. Return `SystemDirective` values describing intended changes instead of mutating the world.
5. Enter with `Command::Plugin` through public `submit()`, `process_command()`, or `enqueue_command()` ingress.

See the runnable [command plugin tutorial](/en/tutorials/command-plugin/).

## Boundary systems

Use a boundary system when supply, demand, allocation, and state changes must coordinate in one settlement. Its contract
declares:

- execution phase and cadence;
- reads, writes, and same-boundary visibility;
- resource offers, reservation requests, and allocation dependencies;
- domain events it may emit;
- required random streams and schemas.

Canwu runs these systems in fixed phase order, validates declared access, performs deterministic allocation, and commits
the boundary atomically. See [phased boundary and allocation](/en/tutorials/phased-boundary/) for a complete example.

## Culture system SDK

The published `canwu-culture` SDK is a developer-facing authoring layer above
`canwu-society`. A content pack declares targets, cohorts, channels,
transitions, institutions, and downstream effects; the SDK validates budgets
and compiles those definitions into an externally immutable, content-hash-bound execution plan.
The runtime completely restores the dirty set, hot-target index, dormant
schedule, and effect-cadence cursors. After explicit society synchronization, retired targets
no longer participate in target-scoped hot work; incremental aggregation remains
follow-up work.

Use `settle_culture_society_boundary` for ordinary host settlement. It prepares
a runtime delta over active, due-dormant, and explicitly observed targets, and
touches society bindings only for targets whose lifecycle changes. The full
`synchronize_society_lifecycle` scan is reserved for load repair and explicit
maintenance checkpoints.

Culture targets have `Active`, `Dormant`, and `Retired` states. A dormant target
leaves the culture hot index while retaining a reactivation descriptor; a retired
target releases dynamic society state during synchronization but keeps a tombstone
and historical evidence. Reactivation is explicit and generation-bound; the
canonical-ingress adapter remains follow-up work. See the [culture and legal institutional systems](/en/architecture/culture-law/).

## Legal institutionalization SDK

The experimental `canwu-law` crate compiles legal authoring definitions into a
deterministic plan and provides jurisdiction relations, institutional seats,
frozen procedures, per-seat participation, a decision outbox, pending legal
intents, immutable legal sources and law versions, stable rules, cases and
rulings, applicability, and succession. Authors must declare clause modality and distinguish legal
competence, defects, validity, and exact origin. Kernel command authorization
does not imply in-world validity. Rights and eligibility clauses also declare
holders, duty bearers, subject matter, standing, and remedy relations. Canonical `LegalMutation` and pending-
intent ingress are revalidated by the event-driven plugin and update the
aggregate atomically in one `DomainDeltaProposal` using its exact record
version. The three-stage outbox adapter persists the expected revision, settles
decision ingress, then proves accepted controller and ticket-open outcomes plus
the exact ticket binding from the persistent decision journal. The proof does
not depend on retaining ingress payloads. Actor contexts come from bounded
holder `KnowledgeQuery` results.

Persisted indexes cover open procedures, deadlines, latest participation,
dispatched outbox identities, due versions, decision outcomes, and dirty rules. Applicability queries require
an order partition and exact compiled profile; succession uses bounded reception
scope and rule-prefix matching rather than inheriting a whole predecessor order by default. Retirement names an exact culture
generation: adoption evidence can retire without deleting enacted law, while
an operative live-level dependency blocks retirement. Only the law's own
review, expiry, repeal, or succession operation changes its legal effect.
Retirement is bounded maintenance: `max_retirement_dependency_records` fails
closed before mutation when the v1 aggregate dependency proof is too large.
See the [culture and legal institutional systems](/en/architecture/culture-law/).

## Fiscal simulation extension

`canwu-fiscal` owns generic fiscal procedure: rules, regional adoption,
assessments, remissions, execution authorizations, audits, and holder-relative
knowledge reports. It does not own silver or grain balances, prices, or transport.
Historical content compiles into an immutable catalog; dates produce periods
and reform candidates rather than applying reforms automatically. After a real
resource operation, a host adapter publishes a typed result and submits a fiscal
execution receipt citing that exact version. See the complete design and three
runnable starts in the [Ming fiscal case](/en/tutorials/cases/ming-fiscal/).

## Lifecycle rules

- Register plugins before commands, scenario validation, or loads that depend on them.
- Provide the same plugin set when restoring a save or replaying a journal.
- Do not retain live runtime references or bypass ingress to mutate state.
- Treat a semantic-hash change as executable semantic change that requires migration or a new version.
- Consume every extension contract through `canwu-api` from application code.

Before implementation, review the [five architectural boundaries](/en/architecture/#five-architectural-boundaries), then
start from the public example closest to your use case.
