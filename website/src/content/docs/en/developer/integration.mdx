Canwu is a headless simulation core. The host owns windows, maps, networking, input, AI scheduling,
and the frame loop. Canwu owns authoritative state, validation, deterministic time, events, and evidence.

## Add the dependency

The current main branch requires Rust 1.88 or newer. Application code should depend only on the public facade:

```toml
[dependencies]
canwu-api = { git = "https://github.com/PeiyuanQi/canwu", branch = "main" }
```

If the application persists Canwu snapshots, pin a published engine release
and upgrade it only with an explicit save migration. The current `main`
branch dependency is for development while the movement API is being released;
do not treat it as a stable snapshot format.

Do not depend directly on `canwu-sim`, `canwu-world`, or another implementation crate. Cargo may resolve them,
but they are not independent compatibility surfaces for application code.

## Minimal host flow

```rust
use canwu_api::{Canwu, SemanticAction, SimDuration};

let mut canwu = Canwu::demo(35)?;
let ids = Canwu::demo_ids();

canwu.act(
    ids.commander,
    SemanticAction::MoveEntity {
        subject: canwu_api::EntityRef::Army(ids.army),
        destination: ids.eastern_territory,
        cargo: Vec::new(),
    },
)?;

let events = canwu.advance(SimDuration::days(1))?;
# Ok::<(), canwu_api::CanwuError>(())
```

Production applications normally construct their own scenario with `Canwu::new(seed, scenario)`.
`Canwu::demo()` exists for examples and prototypes.

## Choose an ingress path

| Entry point | Use it when |
| --- | --- |
| `act(actor, SemanticAction)` | A UI, agent, or tool works with capability-oriented semantic actions |
| `submit(CommandEnvelope)` | The host already owns a typed command and issuer identity |
| `process_command(CommandRequest)` | An external service needs request identity, retry behavior, and recorded outcomes |
| `enqueue_command(...)` | A command must enter at a future simulation time with explicit priority |

Every path preserves the same rule: the host never receives a mutable world reference. Canwu validates authority,
preconditions, and the request before recording an accepted or rejected result.

## Drive time

<Steps>
1. The host reads wall time, turn input, or research workflow progress.
2. The host converts that input into `SimDuration` according to its own speed policy.
3. Event-driven hosts call `advance()`; hosts using daily, turn, or other phased systems call `advance_canonical()` or explicit `settle_boundary()`.
4. The host refreshes presentation state from returned events, boundary receipts, or new read-only snapshots.
</Steps>

Do not feed floating-point frame deltas directly into authoritative state. Continuously rendered clients keep host-side
remainders and presentation interpolation; see the [continuous-time game loop tutorial](/en/tutorials/continuous-game-loop/).
