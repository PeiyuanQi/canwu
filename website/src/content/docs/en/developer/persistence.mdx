A save is not one serialized world struct. Recoverable Canwu state includes the entity registry, domain records, commands, events, boundaries, random evidence, plugin semantics, and validation commitments.

## Saves with plugins

```rust
use canwu_api::Canwu;
use canwu_reference_world::{ReferenceWorldPlugin, demo_scenario};

let (scenario, _) = demo_scenario()?;
let plugin = ReferenceWorldPlugin;
let canwu = Canwu::new_with_plugins(35, scenario, &[&plugin])?;
let json = canwu.snapshot_json()?;
let restored = Canwu::from_snapshot_json_with_plugins(&json, &[&plugin])?;

assert_eq!(restored.checkpoint_hash(), canwu.checkpoint_hash());
# Ok::<(), canwu_api::CanwuError>(())
```

Once state contains plugin domain records, loading must provide the same plugin set used to save it. Plugin names, versions, and semantic hashes are part of the environment commitment.

Old format-5 saves may lack the top-level generic `entities` field. The loader explicitly builds that registry from the validated compatibility projection. It does not depend on the retired `canwu-world` source package.

## Checkpoint journals and exact replay

`checkpoint_journal_json()` combines a validated checkpoint with later journal evidence. Restore it with the matching `from_checkpoint_journal_json_with_plugins()` function.

```rust
let journal = canwu.replay_journal();
let replayed = Canwu::replay_from_journal(scenario, &[&plugin], &journal)?;
assert_eq!(replayed.checkpoint_hash(), canwu.checkpoint_hash());
# Ok::<(), canwu_api::CanwuError>(())
```

Replay requires a matching scenario, engine version, and plugin semantic environment. Long-lived products should pin the engine version, record application and scenario identities, retain migration fixtures, and verify results with checkpoint hashes.

## Counterfactuals and tests

`fork()` creates an independent simulation from the same point. Compare branches with domain projections or checkpoint hashes; every branch still advances through normal command and time ingress.
