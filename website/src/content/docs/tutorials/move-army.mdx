这是理解迁移后边界的最短路径：引擎提供通用运行时，世界模型和移动命令属于可选的 `canwu-reference-world` 整合。

## 运行

```shell
cargo run -p canwu-reference-world --example starter
```

## 执行流程

<Steps>
1. 用 `demo_scenario()` 创建场景、通用实体注册表与参考领域记录。
2. 通过 `Canwu::new_with_plugins(..., &[&ReferenceWorldPlugin])` 注册领域逻辑。
3. 把 `MovementCommand` 包装成 plugin command，再经 `enqueue_command()` 进入规范队列。
4. 用 `advance_canonical()` 推进时间，再通过参考整合的 `snapshot()` 读取军队位置。
5. 保存快照、加载、分支并从 journal 重放，然后比较四个检查点。
</Steps>

## 应该观察什么

- 军队在时间推进后到达目标领地。
- 世界具体类型不是 `canwu-api` 的基础依赖；应用可替换整个领域整合。
- 加载、分支和精确重演都与原运行产生相同检查点。
- Format 7 快照自带规范实体注册与初始场景；旧 format 2-6 存档由内核拒绝，不在运行时隐式迁移。
