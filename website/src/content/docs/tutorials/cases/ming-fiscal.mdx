明代财政不是一组固定税率，而是一套随登记、折银、地区合并征收、战争加派、
朝廷分裂和商人信用持续变化的制度关系。参伍把这段变化拆成可替换的四层，
既能直接运行，也不会把明代专属内容塞进模拟内核。

## 四层交付

| 层 | crate | 负责 | 不负责 |
| --- | --- | --- | --- |
| 通用财政程序 | `canwu-fiscal` | 法规版本、地区采纳、核算、减免、执行授权、审计、改革候选和持有人相对知识报告 | 银、粮、库存、市场价格、运输的真实余额 |
| 明代参考内容 | `canwu-ming-fiscal` | 时期、地区、制度定义、转型、覆盖矩阵、出处和三套历史起点 | 运行时写入、自动改革 |
| 可运行参考整合 | `canwu-ming-fiscal-reference` | 场景组合、插件注册、存档恢复和精确重放 | 特权内核路径 |
| 上层应用适配 | 你的游戏或研究工具 | 在资源、市场、生产或物流领域执行真实转移，再提交精确版本证据 | 绕过规范化输入改写财政状态 |

这四层与 `aggregate`、`group`、`actor` 三种[模拟粒度](/reference/terminology/)
正交。软件层决定代码和数据由谁拥有；模拟粒度决定一条财政范围绑定描述省级
总额、机构群体还是具体经办角色。

## 从明初到南明

编译目录始终保留所选地区和机制的完整时间范围。场景年份只选择当前活动时期，
不会在加载时丢弃其他年代的法规和转型。

| 时期 | 年份 | 游戏中的主要压力 |
| --- | ---: | --- |
| 建国重建 | 1368-1392 | 登记土地与户籍、粮税、徭役、卫所军屯和边粮 |
| 登记制明初 | 1393-1429 | 法定登记逐渐偏离实际人口与可征能力 |
| 折银与财库整合 | 1430-1499 | 粮役折银、中央银库、盐引兑付与商人债权 |
| 地区合并征收 | 1500-1579 | 各地以不同速度合并税役，地方做法先于统一叙事 |
| 一条鞭法扩散 | 1580-1617 | 江南、东南、北方和西南处于不同采纳阶段 |
| 战争加派 | 1618-1643 | 辽饷、剿饷、练饷叠加，法定应征与实际完成进一步分离 |
| 南明财政危机 | 1644-1662 | 多个朝廷、将领、地方财库、盐务和商人信用并存 |
| 郑氏可选延续 | 1663-1683 | 海贸税收与商人军事信用；明确不是中央明朝税制的无缝延续 |

`FiscalHistoricalContextPacket` 通过规范化输入改变历史年份和研究模式。年份可以
让一项改革成为候选，但不会自动改变任何地区。只有通过权限校验的
`ApplyTransition` 行动才会原子安装全部目标法规并停用被取代的法规；
`ChangeAdoption` 只处理不属于已声明转型的采纳阶段管理。因此 1581 年在模型中
是地区比较点，不是“全国一键改革”。

这是一套纵向内容目录，不要求把 1368-1683 年的整个范围放进同一个常驻账本。每个 fixture
选择一个有界年份切片；长期战役可以在已编译范围内推进显式历史语境，但资源与
物流账本的存档、归档或分片仍由拥有它们的上层应用负责。

运行时财政状态最多分别容纳 4,096 条核算、8,192 条执行请求和 8,192 张凭证；
每张凭证最多引用 32 个证据版本，序列化状态上限为 32 MiB。聚合重建使用单遍
索引。超过这些实验性边界时，上层应用必须拆成独立模拟运行或分片；财政扩展
没有原地分区或归档 API，跨分片外部操作 ID 去重也由上层应用负责。

## 704 个显式覆盖单元

参考包包含 8 个时期、8 个地区、11 种财政机制，总计 704 个“时期 × 地区 ×
机制”单元。每个单元都必须解析为以下一种状态：

| 状态 | 使用方式 |
| --- | --- |
| `supported` | 有对应定义与出处，可直接用于模拟 |
| `archetype_fallback` | 只有边界明确的比较原型，不能当作已证实地方事实 |
| `explicit_unknown` | 参考包明确不提供行为，上层应用必须保留未知或自行补充 |
| `not_applicable` | 该机制不适用于该时期和地区 |

宽泛默认声明和具体地区声明通过数字优先级合并。同优先级重叠会让编译失败，
文件顺序不能暗中改变历史解释。每条出处同时记录可支持的论断范围和禁止推断：
登记户数不等于真实人口，法定额度不等于实际征收，朝廷宣称的辖区不等于稳定
控制。

## 从“应征”到“实际完成”

财政程序和资源真值分开结算：

1. `OpenAssessment` 记录某个地区、规则和上层应用定义的核算周期内的应征数量；历史内容时期与核算周期分开。
2. `GrantRemission` 记录经过授权的减免，不能超过应征。
3. `AuthorizeExecution` 允许征收、汇解、支出、储备或退还，但尚未改变资源。
4. 上层资源或物流适配器执行真实操作，并发布类型化结果。
5. `enqueue_execution_receipt` 提交精确类型化结果版本；在运行时结算边界，准入过程会解码每个结果，并逐项核对请求、执行类型、支付形态、资源、来源、目标和单位；持久化凭证的数量与处置结果从证据派生，不由调用方声明。
6. 处置结果可以是完成、部分完成、拒绝或豁免；在单个财政运行时状态内，同一精确证据版本或同一 `（证据种类，外部操作 ID）` 组合都不能结算两张凭证。
7. 聚合按机构、机制、范围、核算周期、单位和支付形态分区；应征、减免与征收、汇解、支出、储备、退还分别记录，只有减免和征收会减少应征未结量。
8. 报告是带不可反推精确真值的量化区间、置信度和证据的持有人相对知识，不是存入 `FiscalState` 的精确真值。

这条路径避免两个常见错误：财政插件凭空生成银粮，或者资源插件反过来决定
一项征收是否合法。市场换算也只保存精确报价版本；参伍不会假定一两白银在
两个地区、两个年份具有相同购买力。

## 三个可运行起点

| Fixture | 适合验证的游戏问题 |
| --- | --- |
| `hongwu-1391` | 登记土地、徭役与漕粮如何共同形成负担；登记量和真实履行能力如何分离 |
| `wanli-1581` | 江南已巩固、东南已实施、北方仍沿用折银规则、西南仅接受改革时，玩家如何协调地区制度 |
| `hongguang-1644` | 领土快速变化时，朝廷、将领、盐务、地区财库和商人信用应当如何保持独立权责域 |

弘光起点把军费征收、商人信用与地区财库拆成三项独立转型，使每个权责域都只能
通过自己的绑定推进。

```text
cargo run -p canwu-ming-fiscal-reference --example ming_fiscal_starter -- hongwu-1391
cargo run -p canwu-ming-fiscal-reference --example ming_fiscal_starter -- wanli-1581
cargo run -p canwu-ming-fiscal-reference --example ming_fiscal_starter -- hongguang-1644
```

追加 `--days <N>` 可以让 starter 在这次 sample cycle 之后继续按确定性的模拟时间
运行；`--cadence daily|monthly|annual` 选择 calendar boundary 标记，`--step-days <N>`
可以覆盖默认步长。月度和年度默认使用固定的 30 和 365 个模拟日，因为 `SimTime`
本身是分钟刻度，不宣称 Gregorian 日历。最后不足一个完整周期时，会用不带 cadence
的边界收尾，避免提前触发月度或年度系统。比如：

```text
cargo run -p canwu-ming-fiscal-reference --example ming_fiscal_starter -- hongwu-1391 --days 365 --cadence daily
```

每条命令都会运行从核算到报告的完整垂直链。参考整合注册
`ReferenceWorldPlugin`、`MingFiscalExecutionAdapterPlugin` 和配置后的
`FiscalPlugin`；恢复与重放辅助函数会提供同一插件集合并运行语义校验。三个起点
都是可替换参考，不是推荐的唯一数值平衡。

## 史料边界

参考包的主要解释框架来自 Ray Huang 对明代税收与财政管理的研究，以及
Richard von Glahn 对货币、盐引和信用关系的研究；地区商业化参考 Timothy
Brook，南明政权序列参考 Lynn Struve，郑氏海上网络参考 Xing Hang。数据文件
还逐条保存引用 URL、可信度、论断范围和禁止推断。详情可直接查看
[`pack.json`](https://github.com/PeiyuanQi/canwu/blob/main/crates/reference-content/canwu-ming-fiscal/data/pack.json)。
