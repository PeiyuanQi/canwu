## 1. 要解决什么问题

`canwu-society` 是一个实验性**社会传播模拟模块**（`social diffusion simulation
module`），在 Canwu 架构中属于**模拟领域扩展**（`domain extension`）。这个示例使用一个
抽象的“新观念”，展示它如何组合群体接触、私人接受、公开表达、组织影响、制度响应和角色相对
估计。案例聚焦传播机制与引擎契约，便于把同一套模型适配到不同的历史或虚构情境。

如果只给每个地区一个“接受度”数值，就无法区分听说过、私下认同、公开表态、
实际参与和组织动员；如果制度政策一提交就直接改写私人认同，模拟也会失去可信度。

这个案例要实现的是：

- 只为真正参与传播的群体和目标保存人口分布，避免创建巨大的稠密矩阵；
- 分别追踪 awareness、private assent、practice、public alignment、组织联系、
  mobilization 和 visibility；
- 让群体接触和组织网络提供传播机会，但由明确的转化规则决定人口如何迁移；
- 让地方机构通过 `DecisionTicket` 选择政策，再由下一次社会结算边界应用制度影响；
- 只向获授权角色返回带误差的估计，不把权威 aggregate 当作玩家可见信息；
- 保存余数、政策、投影和证据，使恢复、fork 与精确重放得到相同结果。

示例使用抽象的“新观念”，不绑定具体宗教、意识形态或历史事件。历史教义、
礼仪、人物、政策名称、文化兼容性、冲突条件和叙事都应由下游领域包提供。
`canwu-society` 当前是已发布但仍属实验性的扩展，也没有从 `canwu-api`
重新导出；这个案例展示的是扩展方法，而不是已经冻结的通用社会或宗教 API。

## 2. 我们如何实现

这个案例组合了以下系统：

| 系统 | 在案例中的作用 | 相关文档 |
| --- | --- | --- |
| `canwu-society` 模拟领域扩展 | 定义 cohort、分布、影响边、制度输入和角色投影 | [通过插件扩展](/developer/extensions/) |
| 结算系统 | 按稳定顺序执行人口迁移，并把制度政策延迟到下一边界生效 | [结算系统](/architecture/settlement/) |
| 决策与权威命令 | 让机构从已有 policy options 中选择，再提交插件命令 | [架构总览](/architecture/)、[接入并驱动仿真](/developer/integration/) |
| 角色相对读取 | 为观察者物化估计，拒绝 ground-truth fallback | [安全读取与呈现状态](/developer/reading-state/) |
| 存档与精确重放 | 保存转化余数、插件状态、投影和 journal 证据 | [存档、重放与分支](/developer/persistence/) |

先运行示例：

```shell
cargo run -p canwu-society --example local_community_diffusion
```

程序会建立市场与村庄两个 cohort。市场中已有少量支持者，市场接触和本地组织
为村庄提供传播机会。第一天先出现 awareness 和少量 private assent；随后地方
机构通过 `DecisionTicket` 选择公开政策，第二天才由社会边界应用制度输入。

### 实现流程

```text
cohort + affiliation target
  -> sparse disposition distribution
  -> influence / organization / institution signals
  -> deterministic integer transitions + persisted remainder
  -> aggregate truth
  -> authorized observer estimate
```

<Steps>
1. 为两个 cohort 创建整数人口，并只为实际参与的 `(cohort, target)` 组合保存分布。
2. 分别表示 awareness、private assent、practice、public alignment、organization tie、mobilization 与 visibility。
3. 用有界的 influence edge 和 organization topology 计算传播压力。
4. 让具名 controller 从已有 policy options 中选择一个，并通过普通插件命令记录待应用政策。
5. 在下一次 daily boundary 中应用制度输入，再按稳定 rule ID 和 cohort ID 结算整数人口转移。
6. 为授权观察者物化带误差的估计；没有 projection 的角色会收到错误，而不是 ground-truth fallback。
7. 保存、恢复、fork，并从 journal 精确重放相同结果。
</Steps>

### 第一步：用稀疏分布表示人口状态

每个 active `(cohort, target)` 保存多个 `DispositionBucket`。一个 profile 把不同
维度分开表示：

```rust
DispositionProfile {
    awareness,
    assent,
    practice,
    public_alignment,
    organizational_tie,
    mobilization,
    visibility,
}
```

所有 bucket 的 `headcount` 必须恰好等于 cohort 人口。不同 target 拥有独立分布，
因此系统不会假设所有社会身份都互斥；不存在的 pair 也不会预先占用
`territory * cohort * target * channel` 的稠密空间。

### 第二步：把传播机会和实际转化分开

`SocialInfluenceEdge` 只提供 reach 与 trust。来源可以是 cohort、organization 或
institutional alignment；下游配置的 `TransitionRule` 再决定这些信号如何推动
人口从一个 profile 迁移到另一个 profile。

迁移只使用整数。小于一人的期望量保存在稳定的 `TransitionRemainder` 中，留到
后续边界继续累计。这样不会因整数取整而丢失人口，也能保证存档恢复和重放保留
同一结果。

### 第三步：让制度政策在下一边界生效

示例的 controller 代表一名获授权人物，并提供两个已有 option。Utility policy
只能选择 option ID；选中的 option 再通过 `set_institutional_policy` 命令写入待
应用组件：

```text
DecisionTicket -> controller-derived authority -> plugin command
    -> pending policy component -> next daily society boundary
```

命令被接受后，示例会立即断言人口分布尚未改变。到第二天，制度 enforcement
可以让 public alignment 比 private assent 更快变化，但它仍不能直接指定“多少人
真心相信”。

### 第四步：为角色生成估计，而不是泄露真值

`projection_for_viewer()` 要求 Canwu 签发的 `ViewerContext`，并且只返回在
`PerspectiveAndReportMaterialization`（角色视角与报告物化）结算阶段已经为该
actor 生成的 `SocietyProjection`。检测率、遮蔽和 false positive 会让估计与真实
aggregate 不同；没有 observer profile 的角色会得到错误，不会自动获得社会根记录。

示例通过 `from_society_snapshot_json()` 恢复存档。这个模块入口会在 Canwu 的通用
存档检查之后，重新核对社会 payload 使用的核心实体引用和所有已物化派生值，然后
示例再验证 fork 与 journal replay 得到完全相同的权威状态。

### 第五步：只输出动员候选，把冲突判断留给下游

`MobilizationBand::Active` 可以产生带人口、组织能力和政策压力证据的
`MobilizationCandidate`，但它不是冲突事件。抗议、镇压、迁移、暴乱、结盟或
战争仍应由独立的政治与安全扩展判断。

## 模拟领域扩展边界

这个模拟领域扩展中的可复用引擎部分是 cohort、稀疏多维分布、确定性迁移、影响边、组织拓扑、
制度输入、政策压力、候选输出和角色估计。历史教义、礼仪、人物、文化兼容性、政策
名称、具体冲突判定与叙事都属于下游领域包。

`canwu-society` 当前已发布，但没有被 `canwu-api` 重新导出。它是实验性
模拟领域扩展，用于验证公开插件契约；当前公开范围覆盖通用传播机制，历史内容与具体领域 API
由下游包定义。

面向更大规模文化系统时，实验性的 `canwu-culture` SDK 会把这些定义编译成有界的文化执行计划，
并提供可恢复的待处理关系集合与热目标索引。当前社会聚合仍使用全状态路径，完整增量刷新属于后续工作。
没有参与人口的目标可以进入 `Dormant` 并离开文化热索引；主机同步 society 后会停用文化计划编译出的转移规则。
随后进入 `Retired` 时，同步操作会释放目标相关动态状态，并由墓碑保留历史。显式重新激活会创建新一代目标。
生命周期概览见[文化系统编写与生命周期](/architecture/#文化系统编写与生命周期)，
完整性能基准（benchmark）契约见[设计提案](https://github.com/PeiyuanQi/canwu/blob/main/docs/proposals/culture-authoring-sdk-and-lifecycle.md)。
