## 先看故事

本案例使用五个合成持有人和没有现实含义的内容代码。初始持有人向指定收件人发送
一份需要特定能力才能解读的符号表现；中继经手人在传递途中截获并复制它。

经手人可以看到完整的符号副本，却没有对应的解法。他知道“拿到了一份东西”，却不能
把它还原成有意义的话。指定收件人收到原件后，请一名有权限的持有人代为解读，得到
一份结果内容，再把结果只开放给收件人和一名复核者查看。

这件事最容易混淆的地方，可以用一句话概括：**看见了，不等于看懂了；看懂了，也不
等于有权替别人发布。**

## 运行

```shell
cargo run -p canwu-information --example encoded_interception
```

示例用 detached ledger 保持完整生命周期清晰可读，再通过权威 `InformationPlugin`
执行“解读者替收件人完成解读”的授权操作。一个持久化的中立权限命令提供精确 claim；
示例随后验证快照恢复、不会重新运行外部解码器的精确重放、压缩证据重建与压缩
checkpoint 恢复。

故事角色对应如下：

| 代码标签 | 故事角色 | 所在地或关系 |
| --- | --- | --- |
| `H-601` | 符号内容的初始持有人 | `NODE-0` |
| `H-602` | 指定收件人和委托方 | `NODE-2` |
| `H-603` | 中继经手人 | `NODE-1` |
| `H-604` | 受托解读者 | 受收件人委托 |
| `H-605` | 受限复核者 | 收件人指定的查看者 |

## 相对时间线

| 分钟 | 故事动作 | 系统记录 |
| ---: | --- | --- |
| `0–1` | 创建需要 `decode_k2` 的 `grouped_symbols_v1` 表现。 | 创建原始 content 和 representation |
| `2–4` | 向指定收件人发起传递，仍在传递途中。 | 创建 addressed dispatch，delivery attempt 进入 `InTransit` |
| `5` | 中继经手人截获符号表现并复制一份。 | 创建 same-content representation copy 和 parent edge |
| `6` | 经手人完整看过副本。 | 记录 access |
| `7` | 经手人用错误的解法尝试解读。 | `decode_k1` 失败，不产生 result content |
| `12–13` | 指定收件人收到原件并接触符号表现。 | 完成 delivery attempt，记录原件 access |
| `14–15` | 受托解读者用正确能力代收件人解读。 | `decode_k2` 成功，生成结果 content 和成功 interpretation |
| `16` | 原始传递在 delivery attempt 终止后完成。 | dispatch 进入完成状态 |
| `17–19` | 收件人把结果只开放给自己和复核者。 | 创建并激活受限 review release |

## 模型验证点

<Steps>
1. 截取首先生成 representation copy；`SameContent` 和 parent edge 说明“这是同一份内容的复制件”，不会把它伪装成指定收件人已经收到的原件。
2. 取得 access 不等于取得 interpretation。`H-603` 可以完整看到暗号副本，但因为只有 `decode_k1`，只能得到一次失败记录。
3. `Failed` interpretation 不允许绑定 `result_content`；`Succeeded` interpretation 必须绑定解读结果。
4. 每次 interpretation 都同时记录输入 access、输入 representation、实际执行者 `performed_by` 和服务对象 `performed_for`，因此能看出“谁看了、谁解了、替谁解”。
5. 定向 delivery 仍按自己的 attempt 状态推进；中途截取不会替换指定收件人的交付证据。
6. Knowledge draft 按持有人隔离：截取者只知道自己的 access 和失败解读，收件人知道自己的 access、受托解读和复核发布，复核者只知道 release 可用；执行解读的人不会因为代办一次操作，就自动得到收件人的全部 knowledge。
</Steps>

## 读完后只记住三句话

- 截到副本，不等于截到对方已经理解的内容。
- 能看到暗号，不等于有能力解读。
- 能替别人解读，也不等于自动拥有替别人发布的权力。

## 可替换的应用层部分

`grouped_symbols_v1`、`decode_k1`、`decode_k2`、节点编号和相对时延都是应用配置。
引擎只需要中立的 representation lineage、delivery、access、interpretation 和
holder-relative publication 契约。真实的暗号规则、传递方式、解读能力和故事后果，
都留给下游插件。
