Canwu 的军事能力属于可选的**模拟领域扩展**（`domain extension`），不是模拟内核的新子系统。`canwu-military` 通过 `canwu-api` 提供军事领域记录、领域命令、边界系统、抽样证据和角色相对投影；`canwu-military-reference-content` 提供版本化规则与内容；`canwu-military-reference` 提供可替换的参考整合包。

## 13 项能力

扩展覆盖一条可持久化、可精确重放的因果链：

1. 建立军队：创建编制、编组、子单位和生命周期。
2. 任命将领：维护指挥链、权限和命令延迟。
3. 招募：连接社会候选人、入伍、训练和装备。
4. 行军：使用角色相对路线规划，并交给运输扩展执行。
5. 遭遇：记录接触、可见性和确定性仲裁。
6. 伏击：记录隐蔽、准备、触发和反侦察。
7. 战术与战略：通过 `DecisionTicket` 绑定行动计划和选择。
8. 战斗结算：分阶段结算战斗轮、伤亡、俘虏、撤退和追击。
9. 敌后行动：支持侦察、袭扰、破坏、渗透、撤离与返回。
10. 补给：提交类型化需求，接收预留、运输和短缺结果。
11. 占领控制：管理对象控制、驻军、安全、抵抗和治理前提。
12. 同化：通过法律、社会和文化确认推进分阶段整合信号。
13. 军政管理：记录军政府办公、政策以及财政和法律程序。

## 所有权边界

军事扩展是军事力量、行动、战斗、占领和军事知识记录的唯一写入者。模拟内核负责时间、规范化输入、权限、调度、原子提交、持久化、精确重放和随机证据。路线规划与可达性属于 `canwu-routing`；移动、保管权、容量与交接属于 `canwu-transport`；资源账户、预留、消费和履约属于 `canwu-resource`；人口、法律、财政、信息与知识分别由对应扩展拥有。军事扩展只提交类型化请求并绑定精确凭证，不直接修改其他领域状态。

所有外部效果先成为提供方拥有的待处理意图、预留或 saga，随后由提供方在自己的规范化边界中结算，并通过确认输入返回军事扩展。查询、命令错误、事件和报告都不得泄露其他角色的军事真值。

## 合成内容声明

参考内容包中的 `riverine-preindustrial` 与 `industrial-front` 是明确标记的**合成**规则剖面。它们用于覆盖不同的组织、运输、通信和补给假设，不是历史事实、历史兵力估计或来源校准数据。

## 示例命令

上层应用通过公开 API 提交类型化领域命令，例如向军事扩展提交 `OrderMarch`，而不是直接修改军队记录：

```text
military.submit(OrderMarch {
  force_id: force_17,
  destination: node_42,
  expected_revision: 8,
  operation_key: "march-17-42"
})
```

命令会经过权限、版本、幂等性、路线快照和边界验证；运输结果以提供方凭证返回，军事状态只在提交后的边界视图中生成投影。
